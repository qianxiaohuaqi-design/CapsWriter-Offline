# CapsWriter-Offline 产品化升级路线图

> 规划日期：2026-10-27。该表管理未来范围，不表示任务均已获得代码实施授权。项目主线：继续保留稳定的离线听写 → 代码精简/架构改造 → 模型下载与推荐 → Windows 安装发行 → 官网 → 跨平台评估。

## 2026-11-02｜V1 产品设计与一次性交接模式（高于下方 2026-10-27 旧任务节奏）

- 当前网页端已完成 7 组 **UI/交互文字草案**，并形成 [V1 整体设计复审 R1](设计/V1-整体设计复审与范围收敛-R1.md)。R1 为建议，**未获统一设计验收/未冻结，也不授权 Codex 实施**。
- 用户已确认沿用旧控制中心视觉，并将开发协作改为：**网页端集中设计 → UI、产品目标与工程路线冻结 → 一次正式交给 Codex → Codex 在授权范围内连续开发、自测、修复直至 V1 技术交付 → 用户集中验收**。重大阻塞和新权限例外处理；推送、发布、部署、重启与破坏性数据操作另行授权。
- 下方 M1-A/B/C/D、M2、R1、P1～P3 的编号作为 **Codex 内部工程里程碑及历史状态** 保留，**不是要求网页端每阶段再发一次新任务**。W01 / M1-A 旧本地回执状态未因本轮设计而自动改变；最终交接时核对本机实际代码和原有 11 项改动。
- V1 范围分级以 R1 的 C0/C1/C2 为**审查建议**，用户统一确认后才能作为正式冻结任务包；不会因网页端写入这些文档而启动客户端执行。

## 产品边界与已确认决定

- Windows **优先发布**，macOS/Linux 为后续独立评估，不承诺目前可运行。
- 主推不含模型的标准安装版，首次启动引导选择和下载模型；保留 Portable 便携版。预装 SenseVoice 的离线即用版作为候选，尚不首发。
- 首次成功安装模型自动启用；之后新增模型需用户确认切换，不能突然打断正在使用的 ASR 服务。
- 模型下载 V1：单下载任务、其他排队；断点续传并核验下载源版本；安装前校验；失败不覆盖旧模型；GUI 关闭但托盘仍存活可继续；完全退出安全停止并保留可恢复状态；客户端与官网共用可信模型清单。
- 用户数据与安装目录分离；兼容现有便携布局；迁移先预览复制验证、不自动删除原目录；卸载默认保留用户个人数据和模型。
- 现有模型识别流水线优先复用；不开展地毯式故障排查，不无理由重写第三方模型代码。
- 对完整 V1 的实施，冻结后按用户确认的**一次性交接授权**由 Codex 自主推进内部里程碑，不再对同一已批准范围逐阶段重复请求许可；新增范围、安全阻塞及推送、发行、部署、付费、服务重启、破坏性数据操作仍分别确认。网页端负责前期整体设计与最终集中复审，Codex 负责本地实施和测试，用户负责设计冻结与最终验收。

## 已发现的重要发布风险（来自 M0，未复测）

1. `make_releases.py` 将 SenseVoice 权重拍平，与 `config_server.py` 需要的嵌套目录不匹配。
2. 无模型时服务启动检查失败，当前控制中心还缺少完整“先打开 GUI → 引导安装模型”的可验证闭环。
3. `web_gui/process_manager.py` 当前将 `model_loaded` 等同于 `server_alive`，端口在线不等于模型就绪。
4. GUI 仅检查必要文件 `exists()`，不足以识别损坏/变体/当前加载状态。
5. 发布脚本可能移除 MIT `LICENSE`，实际发行必须保留版权与许可证声明，并审查依赖和模型各自许可。
6. 路径和发布脚本布局存在不一致；本地未跟踪 `build.spec` 与发布方案直接相关，不允许盲目覆盖。

## 验收规则

- “代码存在”“模拟测试通过”“真实设备通过”“用户确认”分四个层级写证据，不能混为一谈。
- Codex 内部每里程碑仍必须记录受影响路径、基础 SHA、实际修改、测试命令与结果、受保护文件状态、未验证项；**内部回执不等于必须重新网页端交接或逐模块用户正式验收**。
- 一次性交接包必须完整界定已授权范围；涉及原有 11 项本地改动、私有数据、模型及打包仍以保留和可恢复为前提。远端推送、发布、部署、重启或不可逆删除不由普通开发授权自动覆盖；V1 技术交付后才集中提交用户验收。
