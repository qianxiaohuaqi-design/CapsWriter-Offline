## 1. 现有视觉事实与忠实保留原则

- GUI 使用 NiceGUI / PyWebView，窗口设置 `1120×740`，顶部白色 Header、Logo 和 CapsWriter 标题；左右双栏：左侧 `w-64`（约 256px）导航卡，右侧可滚动白色主卡 `p-8`；背景浅灰，强调色以 Amber / Orange 为主，圆角约 `rounded-xl/2xl`。
- 顶部已有服务/客户端状态、刷新、帮助入口；不增加一个平行的 Dashboard 主页面。用户一打开正常控制中心仍落在「通用与交互」（见 `web_gui/app.py` 1110～1150 行）。
- 当前源码明确调用 `ui.dark_mode(value=False)`（约 1021 行），虽有 `dark:` 样式片段但没有在当前读取范围内确认可用主题切换。**V1 默认完整保留现在的浅色风格**；深色不是已验证实现，不能当成“视觉冻结已通过”，如纳入须另列验证。
- 全部 UI 原型必须复用旧 Logo/图标/字体层级/卡片/操作风格（必要时允许局部完善），不以新设计稿替换原成熟页面，不删任何已确认功能。
- 初次配置采用主内容区临时“六步向导”状态层，**不增加第九个导航入口**；未完成且选择跳过时可进入原八项设置，模型未就绪状态被明确提示。

## 3. 全局界面状态与按钮行为

**单一可信状态来源**（需要本地实现时核对 M1-A）：`model_install_state`、`worker_runtime_state`、`server_transport_state`、`dictation_client_state` 四类独立状态。状态必须有当前实例/会话身份与更新时间；控制中心 Header、模型中心、诊断、托盘共享同一来源。原远端 `model_loaded = server_alive` 是不可信的“已就绪”判断。

| 聚合状态 | Header 主文案 | 「语音识别与硬件」/向导主操作 | 「服务与诊断」建议操作 | 普通听写 |
| --- | --- | --- | --- | --- |
| 无模型 | 尚未安装语音模型 | 打开引导/选择安装或本地导入 | 去模型管理 | 禁用并提示原因 |
| 模型下载/校验中 | 正在准备模型 | 下载进度/暂停/查看任务；不能声称可用 | 查看当前阶段 | 只有**另一个真实就绪的活动模型**才能继续 |
| 已安装未加载 | 模型已安装，尚未启动识别 | 启动模型 | 启动/检查服务 | 禁用 |
| 模型加载中 | 正在加载语音模型 | 查看加载状态 | 查看真实 Worker 状态 | 禁用 |
| 当前模型 Worker 已就绪但听写客户端异常 | 听写客户端尚不可用 | 查看当前模型 | 恢复客户端 | 禁用 |
| 完整就绪 | 听写已就绪 | 查看/切换模型 | 显示各组件真实状态 | 启用 |
| 模型加载失败或 Worker 已失联 | 识别暂不可用 | 查看原因/修复/重试 | 诊断/最小恢复 | 禁用，不引用旧成功状态 |

没有模型的用户仍可访问八项设置（历史、备份、AI 设置等非 ASR 功能）；只有真正依赖模型的操作禁用并给出原因。

## 4. 首次引导与主界面路由状态

- **已有模型的旧用户**：进入正常八页设置，旧配置/快捷键与热词优先保留，不强制重跑首次引导。
- **新安装且无可用模型**：显示完整六步向导入口。用户可“稍后设置”进入正常控制中心；右侧模型状态始终可见，仍可重新打开向导。
- **六步**：欢迎/硬件检测 → 推荐或手动选择 → 下载/校验/安全安装 → 模型加载和可选麦克风测试 → 快捷键/输出方式 → 完成摘要。
- **中途关闭/跳过**：进度应可恢复；下载在独立后台真实存活时可继续，否则只标记暂停/恢复，不假报仍下载。
- **首次模型安装**：可自动设为当前模型，只有 Worker 实际就绪后才显示“听写已就绪”；后续安装第二个模型不暗切。
- **状态冲突**：安装/运行/客户端状态各自独立；GUI 页内与托盘需要基于统一真实快照，而不是每页单独按 PID/端口推断。

## 5. 关键交互原型与验收清单

参见 [交互 HTML 草案 R1](prototypes/capswriter-v1-control-center-ui-r1.html)。它只演示**八项导航外壳、当前状态切换、六步向导、模型中心、任务示意和诊断**，不会修改本机资源。由于没有真实 Windows 当前界面截图，本原型只按源码 class 风格复现信息架构，**不能替代像素级视觉验收，也不能声称是用户目前软件真实截图**。

冻结前建议检查：
1. 八项导航顺序、标题和每页既有功能不丢失；除「模型中心」可选改名外无全局导航重排。
2. Header 在“无模型、加载中、就绪、失败”等状态与模型中心、服务诊断一致。
3. 六步向导可前进/返回/跳过/重新进入；点击步骤不执行真实下载安装。
4. 文本编辑后不再自动收起确认框，且不会向错误输入目标写入。
5. 文件转写取消/失败/完整产物/历史相互一致，原媒体和旧字幕有备份/无覆盖机制。
6. 备份导入与卸载的删除范围明确；AI 远程访问与本地 ASR 隐私边界可理解。
7. 真实 Windows 不同 DPI、窗口大小和托盘关闭/退出测试仍属于 **Codex 实施阶段**，原型不可替代。
8. 模型下载真实来源/哈希/许可、发行签名、安装器/官网真实链接必须按最终证据确定，不在原型里伪造。
9. 主题：当前实际浅色界面已知；暗色兼容须验证用户是否确实启用和全页面可用。

## 6. 仍待用户总设计验收的局部选择

- 「语音识别与硬件」是否更名为「模型中心」？推荐改名，但不改变位置和高级设置。
- V1 首发是否按整体复审 R1 的 C0 必做 / C1 可选 / C2 延后范围收敛？
- 是否要求完整可运行的原生深色主题？建议不把它当首发门禁，先忠实保留当前视觉。
- 状态与向导 HTML 原型是否符合用户当前控制中心的真实交互习惯？截图或实际本机验证后再锁定。
