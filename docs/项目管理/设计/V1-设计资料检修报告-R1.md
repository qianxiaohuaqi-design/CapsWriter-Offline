## 二、主要问题与风险门禁

| ID | 基于旧远端源码的事实 | V1 应检查/修复的内容 |
| --- | --- | --- |
| R01 模型误判 | `web_gui/process_manager.py:get_health_status` 将 `model_loaded` 直接等同于 `server_alive`，托盘主要基于 PID | 实际 Worker 就绪、客户端连接、热键可用需独立真实信号；顶部、模型管理、诊断与托盘不能假报“已就绪” |
| R02 未知进程误杀 | `launch_server/restart_server` 可能根据端口 6016 认定/停止服务；`run_app.py` 也将端口占用视为服务存在 | 端口被其他进程占用时须核实进程归属/协议身份，不误用、不误杀；重启前检查活动任务 |
| R03 文件覆盖 | `web_gui/transcription_service.py` 先调用 `ResultHandler.save_results(file,message)` 在输入侧生成文件，之后才搬迁输出 | 源媒体旁已有用户 TXT/JSON/SRT 时，失败/取消/成功都不能覆盖已有文件；隔离临时工作目录和原子提交 |
| R04 配置半写入 | `web_gui/config_manager.py:import_full_config` 依次写入配置项，未观察到完整原子事务与可验证的整体回滚 | 导入前预检、预览差异和备份；注入中途失败后必须验证全量回滚，无法完全恢复应明确列出结果；保护 Key |
| R05 无模型首启 | `run_app.py` 无论 ASR 端口是否启动仍会尝试 `_launch_gui()`；模型菜单主要以必要文件存在判“安装” | **不能推断没有模型必定打不开 GUI**；须在真实无模型/坏模型环境检查 GUI 能否正常加载、导航与向导可用 |
| R06 旧发行脚本 | `make_releases.py` 拍平模型目录并移除 `LICENSE`；`zip_release.py` 排除深层模型文件 | 发布构建修正路径和版权材料，排除私人配置、日志/录音；Installer/Portable 真实验收 |
| R07 外观状态 | `web_gui/app.py` 设 `ui.dark_mode(value=False)`，尽管包含一些 `dark:` 类 | V1 忠实保留当前可确认的浅色 UI；不能声称深色模式已完整可用 |
| R08 发行文档 | 旧 README、控制中心说明以旧 Full/Lite ZIP 和手动安装模型为流程 | V1 发布时与实际 Installer/Portable/下载向导同步更新；在完成前不能声称新安装器已存在 |
