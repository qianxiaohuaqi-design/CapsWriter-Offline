## 1. 架构决定：保留现有内核，增加薄协调层

现有组件来自远端 master d122f8454ad7ddfb96590b521e9b15e31fead45e 的只读源码检查：

| 现有文件/组件 | 当前职责 | V1 最小变更 |
| --- | --- | --- |
| run_app.py + web_gui/process_manager.py | 启动、子进程/端口、单实例与退出 | GUI 与 ASR 解耦；验证进程实际归属、活动任务门禁 |
| web_gui/app.py + control_tray.py | 8 项设置页、GUI 和托盘 | 原有视觉/导航不变；共享可信运行状态 |
| core/server/app.py | ASR Server、Worker/Socket 协调 | 对当前 Worker 加载/退出状态提供可信只读桥接 |
| core/server/worker/process_manager.py | 进程生命周期、ready_event | 复用 Worker 实际就绪信号；同步实例身份和失效 |
| core/server/worker/worker.py、model_loader.py、engines/factory.py | ASR 加载、识别引擎 | 保留，避免重写模型推理；增加必要状态与回归 |
| core/client/app.py | 快捷键、麦克风、热词、LLM、文本输出 | 延续现有输入协议，补回合身份/目标保护 |
| web_gui/transcription_service.py 与 core/client/transcribe | 文件转写 | 继续复用 ASR；隔离写入工作区、防源旁同名文件覆盖 |
| web_gui/config_manager.py、private_config.py | 普通/私有配置 | 导入预检+备份+回滚；Key 脱敏、路径适配 |

逻辑拓扑：桌面 GUI/托盘 → 现有 Launcher 及薄协调层（可信 HealthSnapshot、模型下载/安装、后台任务调度、统一路径/配置、操作门禁）→ 既有 ASR Server/Worker、Client、文件转写 → 原有用户数据与新任务元数据。

协调层是职责描述，并非要求新 daemon、新监听端口或全面重构。只在 GUI 关闭后任务要继续运行且真实测试证明需要时，才考虑将任务管理放到现有 Launcher 所有的后台生命周期；做不到则明确提示任务会中断，并支持下次安全重试。

## 2. 可信就绪状态：直接复用现有 ready_event

源码确认 Worker 的 RecognizerWorker.initialize 加载 ASR 并交给 TaskHandler 后调用 ready_event.set()；Server ProcessManager 已等待该事件。但 GUI 的 get_health_status 仍错误地令 model_loaded 等于 server_alive；托盘亦主要依据 PID。

V1 的只读状态快照建议包括：
- schema_version、observed_at、launcher_instance_id、server_instance_id、worker_instance_id；
- 当前模型 model_id 和 variant、文件完整性、当前 Worker 状态、服务连接身份及存活状态；
- 客户端连接、热键注册、麦克风测试状态（通过/未测试/当前不可用）；
- dictation_available 及脱敏 error_code。

具体接口或 IPC 由 Codex 先检查本地 M1-A 和现有 WebSocket 协议后决定。优先做向后兼容的本机只读查询，不扩大 LAN 暴露或未经授权的重启/删除接口。ready_event 触发后也必须确认关联当前仍存活的 Worker，不把历史成功、旧 PID、端口在线当作当前可用。模型状态、服务状态、客户端状态分开；顶栏/模型中心/诊断/托盘从同一逻辑快照取得结果。麦克风未测试不得显示测试已通过。

## 3. 路径、模型与个人数据

沿用本地 M1-A paths/catalog/status 的真实契约，不在网页端凭猜测新建第二套路由。目标是：
- 程序只读资源、FFmpeg、许可证和版本 manifest 由 Installer/Portable 构建目录读取，不依赖工作目录始终为源码根；
- 安装版配置/私有凭据/热词/模型/历史/日记/录音/转写/日志各有可写数据根，独立于程序安装目录；Portable 有明确随包迁移的数据根；
- 旧模型及旧文件原位读兼容；迁移只能先预览、备份、复制校验、改引用，默认不移动、不删旧目录；
- 下载缓存与已安装模型互相隔离，用户自己放置的未知权重默认只读、不在卸载程序时删除；
- 新任务元数据小而可靠，不含 API Key 或语音原文，支持异常恢复；原有 JSONL、Markdown、配置文本无须全部迁移 SQLite。

元数据技术可以选择小型 SQLite（事务/幂等）或安全原子化 JSON 日志（简单任务）；必须证明并发、崩溃后一致性，不能基于偏好强行引入大型基础设施。

## 4. 模型下载/安装/切换事务

1. 模型源清单：型号+变体、版本、合法来源、模型许可、所需文件路径/结构、哈希与后端要求。未核实来源/许可的模型不开放一键安装。
2. 一个活动下载，其余排队；下载 ID 和来源身份记录持久化；断点续传前检查内容长度、ETag/版本等来源证据，变化时从头下载，禁止不可信拼接。
3. download → verify → safe extract → stage → atomic commit → load 是不同阶段；100% 网络下载不代表模型已可用。解压阻止路径穿越、非法链接、越界写入，失败不覆盖之前可用模型。
4. 初次成功安装且当前没有可用模型时，可自动激活；之后新增模型只安装不暗切。切换必须先处理录音/转写活动任务，再加载新模型；新 Worker 真实就绪后更新当前配置，失败尝试恢复 last_good_model，恢复也失败时如实报告。
5. 完全退出须安全暂停下载并写回恢复元数据；如果托盘/下载控制器还真实存在，允许关闭 GUI 后继续，不能伪报后台下载。

## 5. 听写、转写、AI 和并发调度

- 保留长按/单击与直接写入/确认后写入；识别结果按 dictation_turn_id、目标窗口身份和版本关联，禁止迟到 AI 消息、上轮结果覆盖用户已编辑文字；确认框修改后不再自动关闭。
- 真正写入前校验原窗口仍是合法目标，失效时保留文字供复制；不能将复制和粘贴混成一个未经用户授权的动作。
- 在线 LLM 只在用户启用和配置后发送相关文字；失败保留本地 ASR 原结果，Key 不出现在日志/诊断/发行包。
- 文件转写复用现有 FileTranscriber/ResultHandler，但现有实现先在源媒体旁写 TXT/JSON/SRT 再搬迁。V1 必须先重定向到 task_id 专用暂存区，再校验并原子发布到应用拥有的输出目录，不能碰原媒体或源旁已有字幕。
- 文件转写任务保存 task_id、源文件引用、参数、阶段、产物与错误，不保存用户原始媒体；运行中退出后可恢复任务列表并从源文件起点重试，不假称从识别百分比处续传。
- 识别 Worker 若无法兼容多任务并发，普通实时听写优先，文件任务须排队或在安全边界延后；活动录音/转写期间模型切换和服务重启须等待或经过明确确认。
- 取消是异步请求，只有关联 Worker/FFmpeg 已确实停止、晚到产物被屏蔽后才可显示已取消。
- 源码旧 transcription_history.py 使用字符串 startswith 做目录归属校验，需按真实文件系统路径归属/链接和管理目录约束保护删除，不让兄弟路径误通过校验。

## 6. 配置、隐私与发行边界

- 配置导入走 schema/允许列表检查 → 差异预览 → 旧版字节备份 → 安全提交 → 读回核验；失败回滚并说明无法恢复的项，不保留半成功伪状态。
- private_config.py 旧版保留 Key 于本地明文 JSON，不能宣传“已加密”。最少应防止 Key 泄入导出包、日志、诊断、公共构建和源码。升级存储介质须核实旧档案兼容并得到用户设计确认。
- 旧热词/正则支持外部直接编辑，保存时校验非法正则及外部修改冲突，不静默覆盖。
- Installer（Inno Setup 优先候选）+ Portable 同一可信二进制构建输入，默认不带大模型，统一依赖和许可证清单；默认安装当前用户、开机启动关闭，正式实机验证后确定。
- 发布脚本需修复 SenseVoice 目录拍平与 LICENSE 被删除问题，不能直接对用户的工作目录运行破坏性清理。
- 官网使用真实版本/SHA/架构/下载文件/发布链接，未发布时禁用下载；静态站完成不等于已公开部署。
- V1 优先手动安全更新+版本检查；静默差分自动更新、账号/云同步、macOS/Linux、完整专业字幕编辑器不属于基础发行范围。

## 7. 工程边界与开放事项

不重写第三方 ASR、不推翻既有 NiceGUI/PyWebView、不替换八项导航、不重建整套数据库、不为 UI 示意生成真实下载任务。源码 M1-A e7cc1e2、W01 和 11 项本地改动尚未由网页端直接读取，未来 Codex 先只读核实，再决定文件级实现，不用 reset/clean/pull 清洗本地工作区。

本设计仍需用户整体审查，并与发布门禁一起冻结后才构成唯一 Codex 实施包。
