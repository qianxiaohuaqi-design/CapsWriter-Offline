## 1. 现有能力与风险概况

- `web_gui/app.py`「本地数据管理」有输入历史搜索、全文和原始文本查看、复制、保留上限、启动自动清空、日记、录音、转写输出、日志和缓存操作；清空输入历史不等于删除旧的日记、录音、模型、配置或转写输出。
- `core/client/output/input_history.py` 将最终输出写入 `web_gui/input_history.jsonl`，并有从已有日记回填显示的兼容逻辑；`input_history_cleared_at.txt` 是旧日记回填的清理分界。删除语义需要特别区分“清空 GUI 展示/历史索引”和“清理所有相关实际数据”。
- `web_gui/ai_panel.py` 已实现多个 API 档案、服务商/Base URL、API Key 输入、获取模型列表、默认润色开关、独立角色、触发词、自定义提示词、角色绑定档案、输出模式与确认浮层配置；已有翻译、小助理、大助理文件。
- `web_gui/private_config.py` 将 API Key 放在本机 `web_gui/private_config.json`（普通 JSON 明文），并根据角色/档案/服务商优先级解析；不是 OS 凭据保管箱，不应向用户宣称“已加密”。
- `web_gui/config_manager.py` 有写入前备份、配置导出/导入、API 档案、角色配置和旧字段迁移；导出明确排除 API Key、模型、录音、历史、日记、日志和转写输出；但是恢复/导入不是已验证的全量事务，且角色文本移除 Key 主要依赖部分正则格式，V1 需要对合法导出范围与泄密规则做安全审查。
- `web_gui/app.py`「热词与替换规则」有 `hot.txt` / `hot-rule.txt` 编辑、开关、阈值、保存/刷新和打开原文件；应检查规则校验与保存冲突，保持专业用户的直接编辑能力。
- 旧版数据路径与源码、Portable、安装版的位置需要承接 M1-A 路径契约；不能通过 GUI 改造搬走或删除真实用户数据。

## 2. 不改导航的页面规划

保留原有「本地数据管理」「AI 润色与角色」「热词与替换规则」「配置备份与迁移」四页，以及「服务与诊断」的独立入口。每页只做局部交互增强，不合并导航，也不牺牲已存在的高级操作。

### 2.1 本地数据管理

**页首信息区**：明确显示“本机存储”；数据类型包括：输入历史索引、每日听写日记、原始录音、GUI 文件转写输出、日志、缓存和配置。仅当程序确实统计时显示空间使用量；统计失败显示“暂无法获取”，不能出现假总量。

**历史内容卡**：保留搜索（正文、应用、角色）、展开/折叠、复制、原始识别与最终输出对比；旧日记回填条目须标注来源，以免“清空输入历史”误被理解为彻底销毁日记正文。

**保留策略卡**：保留条数上限、启动自动清空和相关帮助。现有用户设置不覆盖；新装默认值最终从真实初始配置确定。

**数据清理卡**：每种清理项单独列出影响范围、预计文件数或大小（可靠时）、不会删除什么、是否可恢复；误删风险较高的永久删除必须二次确认。 
- 清空历史索引：只影响 JSONL 及回填显示规则，不删除日记、录音、转写结果。
- 清理 GUI 转写产物：仅可处理应用自身管理目录，不触碰原始媒体；路径归属必须可靠验证。
- 日记/录音：独立选择并清楚显示不可恢复与隐私风险，默认不随“清空历史”清除。
- 日志/缓存：不要删除正在写入的文件或依赖中的任务缓存。
- 配置与模型不属于“清空历史”的隐含对象。

**用户隐私**：不得默认上传录音、转写内容、日记、搜索内容或日志；如果用户主动调用在线 AI 模型，必须明确相关输入将发送给配置的 API 服务商，而不是沿用“所有数据均只在本机处理”的过宽措辞。

### 2.2 AI 润色与角色

**默认 AI 润色卡**：显示总开关、实际选中的 API 档案与模型、结果输出方式、连接/配置状态。没有档案时显示“普通离线听写不受影响”，无需注册账号，也不将联网 AI 视为首次启动前置要求。

**API 档案管理**：保留多档案、增删改、模型列表获取、默认档案设置与不同角色绑定；密码框默认遮蔽 Key，不在通知/导出/日志展示明文。模型列表获取需要显式动作及错误反馈，API 调用失败不能破坏离线听写；“连接测试成功”不能仅凭 Base URL 形式合法判定。不要自动将已有老配置迁移为失效空值。

**角色列表与编辑器**：保留翻译、小助理、大助理和自定义角色，显示启用状态、触发词、绑定档案/模型、结果输出模式。编辑页保留系统提示词、热词注入、上下文、思考选项、读取选中文字、输出浮层和参数；普通项在前，高级折叠。删除自定义角色需二次确认，保留现有文件备份逻辑并防止影响其他角色；默认内置角色的误删除保护待统一决定。

**敏感行为提示**：
- “读取选中文字”单独说明触发后会暂时读取当前选择的文本，若角色使用远程 API，所选内容可能发送给服务商；默认继承旧用户设定，不偷偷打开。
- “保留上下文”明确实际为当前角色的上下文行为，不等同于永久本地历史或跨设备同步。
- “使用在线 AI”说明 API 供应商可处理所发送的语音识别文字；关闭 AI 或网络失败时本地语音识别功能仍可正常运行。

**输出错误降级**：API 超时、服务商拒绝、模型不存在、缺少额度或角色绑定失效时，先保留真实离线 ASR 文字，再提示“AI 处理失败，可使用原识别结果”；若原设定为确认后写入，不应悄悄强制打字。AI 浮层遵守上一份草案“用户修改文本后不自动关闭”和防错窗口的规则。

### 2.3 热词与替换规则

保持现有独立页面、阈值、启用开关、文本编辑器和“打开文件/保存/刷新”。改进四点：

1. **语义说明**：普通热词用于纠正常见词、人名、术语；正则用于精确匹配与替换，不应把普通热词宣传成专业词自动翻译。
2. **安全保存**：写入前校验文件可读、编码与基础规则格式，遇到无效正则显示具体行号和原因，不把错误规则直接标为有效；允许用户回退草稿与旧版备份。
3. **外部编辑冲突**：若其他程序在编辑期间修改 `hot.txt` 或 `hot-rule.txt`，保存前检测磁盘内容已变化，提示比较、重新加载或明确覆盖，不静默覆写。
4. **生效时机**：保存后显示“下一次听写生效”或实际真实生效状态，不无根据地显示服务已应用；编辑过程中不影响当前录音回合。

预设热词模板、批量导入和词库管理系统不是 V1 必需；沿用文本文件编辑入口即可。

### 2.4 配置备份与迁移

保留现有备份/导入/导出页面、自动备份和历史备份管理，不将模型、用户录音或日记混入普通设置包。

**导出**：
- 明确“只导出常用设置、热词/规则、角色配置与 API 档案结构，**不含 API Key**，也不含模型、录音、听写历史、日记、文件转写输出、日志”。
- 导出前对全部字段/角色文本/可扩展自定义字段做允许列表与敏感项检查，不依赖某个单引号格式的正则清除便声称绝对无凭据；尽可能使用结构化配置抽取。
- 输出文件路径可选，并提示备份可能包含用户自定义提示词、角色设定和热词，仍属需要私密保管的个人资料。

**导入**：
- 选择 JSON 后先检查版本/结构和字段类型，展示将要修改哪些类别、保留什么以及冲突处理；默认备份当前配置，再允许用户确认应用。
- 任何配置导入应具有全量预检 + 可追溯的备份/回退能力，发生失败不得留下 UI 显示“全部成功”但部分配置已改的状态。
- 遇到未来版本未知字段：保留原有内容并提示无法直接应用的部分，不擅自删除或静默覆盖未知定制项。
- 无 API Key 仍可导入角色与 API 档案结构，但显示“需要重新填写密钥才能联网调用”；导入结束不能自动替用户删除旧私有密钥，是否清理由用户明确决定。
- 旧 Portable 用户迁到新安装版：仅在预览路径差异/文件冲突/目标空间后复制、验证并切换引用，不自动删除原有目录；卸载安装版默认保留模型和私人数据。

**自动备份/历史版本**：
- 显示备份时间、来源文件、影响范围以及恢复前确认，恢复成功需重新读取确认；
- 清除备份须独立二次确认，不能与“清空历史记录”共用动作；
- 私有 Key 存储不默认纳入公开导出或一般配置备份，备份与权限策略需工程审查。

## 3. 交互状态与异常反馈

| 场景 | 用户可见提示 | 核心规则 |
| --- | --- | --- |
| 历史为空 | 暂无听写历史 | 不把日记/录音的存在误判为历史未清空 |
| 输入历史已清空 | 历史列表已清空；日记/录音/转写文件不受影响 | 明示数据范围 |
| 日记或录音保存失败 | 保存失败，可查看本机目录权限/磁盘 | 不影响本次识别结果取回 |
| 未配置在线 AI | 未添加 API 档案；离线听写可正常使用 | 不阻塞启动 |
| API Key 不存在或测试失败 | 检查 API 档案与连接 | 不输出密钥 |
| 角色绑定失效 | 无法调用指定档案，可重新选择 | 保留角色提示词，保留原识别文本 |
| 热词/正则错误 | 显示具体行、原因、保存/生效状态 | 不静默部署坏规则 |
| 热词文件外部改动 | 磁盘文件已变化，需选择处理方式 | 不覆盖用户外部改动 |
| 备份导出 | 提示包含/不包含哪些数据 | 保护 Key 和原始数据 |
| 导入不兼容 | 显示差异、版本与可恢复选项 | 不部分覆盖后误报成功 |
| 用户删除或清理 | 精确说明会删除哪些文件，二次确认 | 真实路径校验与回退边界 |

## 4. 技术与验收边界（将并入 V1 单次交接包）

- 页面只使用现有 NiceGUI/PyWebView 视觉与导航，除必要的 UI 逻辑一致性、输入校验和状态展示外不做重型框架改造。
- 保留旧 JSONL 历史、日记 Markdown、录音、GUI 转写输出、`LLM/*.py`、热词文件，以及有备份的 Python 配置兼容读取；真实路径按 M1-A 本地契约核验。不能凭旧远端路径替换本机已实现的新状态模块。
- 重点代码验证：`web_gui/app.py`、`web_gui/ai_panel.py`、`web_gui/config_manager.py`、`web_gui/private_config.py`、`core/client/output/input_history.py`、`core/client/llm/`、`hot.txt`/`hot-rule.txt` 及窗口/剪贴板交互。
- 安全测试：输入历史清理不删日记、跨来源历史标识、旧配置迁移、角色启停/档案绑定/失效、API 请求参数与隐私提示、Key 脱敏、不受控导入防泄密、角色删除备份、外部编辑冲突、非法正则、数据目录只读/权限不足、原文件哈希保护。
- 在本机实际触发在线 API 前应获得相应外部调用授权/许可，勿为测试自动产生未批准费用。
- 旧用户的配置、热词、角色、历史与私人 API Key 不得丢失、暴露或静默重置。自动化测试通过、实机通过和用户体验验收分开记录。
- GitHub 协作文档只是方案记录，**不是当前本地实现已完成，也不表示已交付 Codex**。

## 5. 待产品总体冻结时决定

1. **数据清理**是否新增一张统一的“清理预览”，但保持原清空历史/日志/转写输出的独立入口？建议增预览，避免误解。
2. **API Key 管理**：V1 是否迁入 Windows DPAPI / Credential Manager 等 OS 存储？建议工程评估兼容与备份迁移后再定，至少保证不以明文出现在导出、日志和远端仓库；不要承诺跨平台统一的加密实现。
3. **导入策略**：默认“预览差异→备份旧配置→一次应用→校验→异常回退”；是否允许“只导入选中类别”？建议 V1 支持主要类别勾选，其他复杂冲突暂按保守保留。
4. **AI 功能默认**：保留老用户设置，新用户只在已有可用 API 配置且显式启用时使用在线 AI；离线语音识别默认可独立完成，无需云端。
5. **删除角色**：已内置角色建议仅允许禁用或恢复默认，自定义角色允许二次确认删除并留备份。
