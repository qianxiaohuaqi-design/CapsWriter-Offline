# CapsWriter-Offline V1｜首次启动与模型安装交互草案

> 2026-11-02｜状态：网页端设计讨论稿，**未获用户逐项验收、未冻结、未授权 Codex 实施**。本文件不替代现有 `docs/项目管理/当前交接.md` 或 W01 / M1-A 回执。产品设计完成后再一次正式交接 Codex。
>
> 已确认：**沿用当前桌面控制中心的视觉风格**，保留已有浅色/深色主题、卡片、字体、配色和成熟功能；不开展全局 UI 换肤。Windows 优先，首发标准安装版不捆绑模型，保留 Portable；现有 ASR 及数据保护规则继续有效。

## 一、目标与优先级

- 无本地模型时也能独立打开控制中心、查看说明与设置，不能陷入启动失败循环。
- 普通用户可通过一次引导完成硬件检查、模型选择、下载/安装、加载、麦克风测试与快捷键设置；原有正常用户不应被重复打扰。
- 模型 **文件已存在 ≠ 已校验 ≠ 加载成功 ≠ 当前可听写**。页面必须使用真实状态，不能只凭端口、PID 或 `exists()` 宣称就绪。
- 可随时跳过/退出向导，返回控制中心；不强迫联网、登录或填写模型 API。离线听写与在线 AI 润色分开。
- 首版重用既有 GUI 样式与设置模块，新增流程与状态反馈，不删除已有热词、音视频转写、角色和历史能力。

## 二、入口与导航（拟定，待设计验收）

- 首次启动：启动器先允许 GUI 独立进入；检测原有模型、配置和本地安装状态；没有真正可用的 ASR 时显示首页的配置提醒和“开始设置”入口，并可进入向导。
- 已有可用模型：直接打开原有控制中心，不反复弹出首次向导；加载中明确显示等待而不是已就绪。
- 模型不完整/损坏：保留配置并显示修复入口；不要删除用户已有模型或覆盖配置。
- 中途关闭、跳过：向导进度可恢复。用户在控制中心模型管理页可再次打开向导；正式切换模型须独立确认。
- 优先将向导作为当前控制中心内的整页/主内容分步流程，沿用原组件；不要另开独立弹窗或重排全部导航。

## 三、六步体验草案

| 步骤 | 页面目的 | 核心元素 | 下一步条件与异常 |
| --- | --- | --- | --- |
| 1 欢迎与环境检查 | 解释完全离线识别与准备状态 | 软件用途、本地/隐私说明、OS、CPU、RAM、可见 GPU、剩余磁盘与检测结果；“继续”“稍后设置” | 检测失败可使用保守默认值并手动选择，不要把无法识别 GPU 当阻塞 |
| 2 选择模型 | 推荐适合当前机器的模型 | 1 个主推荐+可展开其他已支持模型；语言、模型大小、硬件需求、下载量、来源/许可、推荐依据、手动导入入口 | 首发以受支持且有合法可信来源/校验信息的模型为候选；性能未知不可伪称极速 |
| 3 下载、校验与安装 | 取得可信模型并保证可恢复 | 下载量、速度、阶段、剩余空间、暂停/恢复、重试、查看来源、稍后继续；状态从下载→文件校验→安全解压→安装完成 | 单下载任务、其他候选排队；断点续传前验证来源版本，哈希不匹配拒绝启用；失败保留旧模型 |
| 4 模型加载与麦克风检查 | 证明当前实际可用 | 加载中/就绪/失败、麦克风列表、手动开始/停止测试、音量反馈和本地试录识别文字；“跳过测试” | 文件安装成功不等于运行就绪；无权限/无麦克风/加载失败分别提示；测试不默认上传或保存音频 |
| 5 快捷键与输出方式 | 确定日常听写习惯 | 当前默认/现有快捷键、按住说话与单击切换、直接写入与确认后写入、冲突检测及引导体验 | 尊重旧设置，不强迫重新绑定；冲突可选其他键；权限失败显示具体解决说明 |
| 6 设置完成 | 可明确开始使用 | 当前模型、就绪状态、快捷键、输出方式摘要；“开始使用”“查看控制中心” | 仅真实就绪才展示“可以开始听写”；跳过麦克风测试时标注“麦克风未测试” |

### 步骤转换原则

1. 正常模型已有：可跳过模型安装步骤；现有用户仍以原控制中心为入口。
2. 无网络：下载页提供本地导入或以后安装，主页保持可访问；无网络不是软件整体错误。
3. 离开下载页：托盘/后台仍存活时任务可继续；完全退出时有界安全暂停并保存可恢复状态，不能说后台仍下载。
4. 下载完成后首次安装模型：经校验并启动成功时自动设为当前模型；后续另装模型不可暗中切换、打断正在使用的识别服务。
5. 返回上一步不应撤销已验证的下载结果；重新选择模型应明确告知正在进行的任务如何处理。
6. 向导完成与“模型真实可听写”分开记录；可跳过向导，但首页不可伪称已就绪。

## 四、状态与界面文案草案

| 状态 | 首页/向导建议文案 | 主操作 |
| --- | --- | --- |
| 无模型 | 尚未安装语音模型 | 安装模型 / 稍后 |
| 下载暂停 | 模型下载已暂停，可继续 | 继续下载 |
| 下载中 | 正在下载模型（显示阶段与实际进度） | 暂停 / 查看详情 |
| 校验中 | 正在验证下载文件 | 查看详情 |
| 安装失败 | 模型安装未完成，原有模型未被替换 | 重试 / 查看原因 |
| 已安装未加载 | 模型已安装，尚未启动识别 | 启动识别 |
| 加载中 | 正在加载语音识别模型 | 查看状态 |
| 已就绪 | 语音输入已就绪 | 开始使用 |
| 加载失败 | 模型无法启动（呈现真实原因） | 重试 / 诊断 |
| 麦克风未授权 | 无法访问麦克风 | 打开系统权限说明 |
| 部分可用 | 文件转写/历史等功能可用，语音听写尚不可用 | 继续设置 |

安装状态（未安装/部分/待校验/已校验/损坏等）与运行状态（未启动/加载中/就绪/失败等）**不应混入一枚单一布尔值**；具体状态枚举优先复用并复核本地 M1-A 的 `paths.py` / `catalog.py` / `status.py`，不预先定义第二份源码接口。

## 五、界面落位及兼容性

- **首页**：仅增加一张依据状态变化的主状态卡及相应入口；继续使用现有主题和卡片语言。
- **语音识别与硬件/模型管理**：整合模型列表、下载入口、活动模型状态及高级硬件设置；保留现有可编辑设置和高级控制。
- **向导内容区**：左/上方保留一致的阶段进度，主体使用现有卡片、输入和按钮样式；底部“返回 / 稍后 / 继续”位置一致。
- **托盘**：显示下载与模型加载的真实状态；完全退出与仅关闭 GUI 的区别明确。
- **既有历史/热词/文件转写/AI 功能**：不因缺失模型启动而导致资料不可查看或丢失。
- **隐私**：麦克风测试须显式开始；识别文字与音频默认不上传；模型下载联网只用于用户确认的下载操作；不回传本机私人配置。

## 六、工程实现约束（供未来唯一交接包引用）

- GUI 生命周期独立于 ASR 服务生命周期；无模型时 GUI 正常启动，依赖 ASR 的按钮显示不可用原因。
- 模型加载成功信号须与实际 worker/进程版本绑定，处理旧状态、重启、异常退出及竞态；不能 `model_loaded = server_alive`。
- 不能仅凭文件存在判定模型完整。可信清单、来源版本、哈希、许可元数据和磁盘操作需要真实核对；未知数据留空或标记待验证。
- 模型、日志、配置、用户历史和热词原字节保护；源码、Portable 与安装版路径以后续核验的 M1-A 契约为准。
- 下载器校验并安全解压，禁止路径穿越和覆盖旧模型；安装状态原子化提交，失败保留可恢复下载缓存。
- 模型技术验证、真实设备/麦克风验证、用户 V1 验收相互独立。
- 本文件只做设计，不授权当前执行 M1-B/C/D，也不授权推送业务代码、安装、部署或重启。

## 七、待确认的 UI 决策

1. 向导是否所有新安装用户首次都显式展示欢迎页，还是只在“无可用模型”时主动提示？建议：已具备可用模型的老用户不打扰；新装无模型主动进入向导，但可跳过。
2. 麦克风和快捷键测试是否强制通过才能结束？建议：均可跳过，但状态明确标记尚未实际测试。
3. 首版模型选择是只有一条“推荐方案”还是 1 推荐 + 展开完整模型列表？建议后者，避免把硬件检测误差变成强制选择。
