## 1. 现有功能核对（远端 master d122f845）

- `config_client.py`：已有 `shortcuts`，示例 Caps Lock 和 X2；每条快捷键支持 `hold_mode`，支持 `output_destination=typing/overlay_preview`、`restore_clip`、`paste_apps`、`enter_apps`、`history_max_items`、录音/日记保存等。
- `web_gui/app.py`：「通用与交互」已有快捷键捕获、模式切换、浮层开关、输出方式、确认浮层关闭策略、超时设置、兼容应用列表；「热词与替换规则」已有编辑与备份。
- `core/ui/modern_overlay/pill_overlay.py`：录音声波/文字反馈、识别处理中状态、最终识别显示、可编辑确认框、复制、写入光标位置、Esc 关闭与按字数自动关闭。当前实现会在焦点离开编辑框后恢复自动关闭倒计时。
- `core/client/output/result_processor.py`：有临时识别、最终结果、繁简/热词/去标点/正则、按应用决定打字或粘贴、可选 LLM/角色处理、历史/日记/录音记录。

## 2. V1 总原则

1. 保留桌面控制中心的导航、卡片、浅/深主题与既有胶囊浮层风格；不新建“语音输入”顶级导航来替代原有八项设置入口。
2. 用户无需打开控制中心即可日常使用全局快捷键听写；控制中心用于设置和诊断，浮层为轻量反馈而非持续占屏的大窗口。
3. **录音、识别、文本处理、结果展示、写入、失败**必须是可辨认的状态。服务器端口在线不代表可听写；未就绪、断网（仅云端可选功能）和麦克风失败需要准确提示。
4. 原有快捷键、多快捷键并存、按住说话/单击开始结束、直接上屏/确认预览都保留。修改设置后清楚提示生效时机。
5. 普通离线听写不依赖 AI API。热词/正则是本地能力；可选角色/润色不成功时保留原识别文本，不丢失用户结果。
6. 编辑过的文字不能因自动倒计时无提示消失；结果展示失败也不能无视用户“确认后写入”的选择而静默切回自动打字。
7. 历史、录音、日记、日志及剪贴板按原有隐私边界保护；不因 UI 重构清空已有数据。

## 3. 日常听写主流程

用户在其他应用输入框获得焦点 → 用已设快捷键开始（长按/点击） → 声波/文字浮层反馈“正在录音” → 停止录音后显示“正在识别” → 若模型已就绪返回最终识别文本 → 本地热词/规则/格式化 → 可选 AI 角色处理 → 根据输出模式：

- **直接写入**：在原目标应用光标位置尝试上屏。只在确认目标和执行结果的边界内提示成功；不对不能确认的系统级按键事件声称“已写入成功”。
- **确认后写入**：显示原有可编辑浮层，允许修改、复制、写入光标位置或关闭。优先恢复原输入目标；目标窗口已失效或无法安全聚焦时，保留文本并提示改为复制/手动粘贴，绝不粘贴至错误窗口。
- **故障分支**：没有可用模型、录音权限不足、麦克风占用、无有效声音、识别超时、服务异常、焦点丢失等分别显示可理解原因和重试/模型中心/诊断入口。

## 4. 录音胶囊与状态

| 阶段 | 视觉 | 主要信息 | 后续行为 |
| --- | --- | --- | --- |
| 待命 | 默认隐藏浮层 | 托盘/控制中心显示真实就绪状态 | 等待快捷键 |
| 录音中 | 沿用底部居中橙色声波胶囊；文字模式保留 | 录音中、音量反馈、适度时长提示 | 松开/再次点击结束 |
| 正在识别 | 保留同位置，不再播放“录音中”动效 | 正在识别/等待结果 | 成功进入结果或失败 |
| AI 处理中（可选） | 延用原有处理中样式 | 正在润色/翻译（仅实际触发时） | 成功显示结果，失败保留原识别 |
| 已完成、直接写入 | 短暂展示最终文本或简短结果反馈 | 结果已生成；输入行为不确定时不写“写入成功” | 非编辑状态正常自动收起 |
| 确认浮层 | 沿用现有白底、橙色强调、可编辑文本区域 | 原识别/处理后的内容、复制、写入、关闭 | 用户自行决定 |
| 错误/不可用 | 不无限转圈、不过度遮挡输入框 | 具体失败原因/可恢复入口 | 释放按键/录音资源，允许下一次尝试 |

不把普通中间识别文本当最终结果；同一回合采用 task/session 身份，过期的中间包、晚到的 AI 文本不能覆盖新回合或用户已编辑内容；需要考虑连续长按、双快捷键和 Esc/取消竞态。

## 5. 确认浮层交互细则（建议 V1）

- **未修改内容**：沿用现有用户配置的自动/手动关闭，自动模式可按长度延长；自动关闭只隐藏结果框，不自动写入。
- **开始编辑或文本确实被修改**：立刻暂停倒计时；若发生实际编辑，整轮转为“需用户主动结束”，焦点离开也不恢复自动关闭，直到用户点击“写入”“关闭”或作出明确操作。
- **复制**：复制当前编辑后文本，显示明确反馈。复制与写入是两个动作，不将复制视为授权粘贴。
- **写入光标位置**：使用当前确认的目标窗口；原目标已关闭、被替换、权限不足或焦点无法恢复时不向未知窗口粘贴，提示“无法确定目标，已保留文本供复制”。
- **关闭/Esc**：关闭当前预览，不等于清空全部历史，也不应误取消别的回合；有未保存编辑且不再自动保留时需避免丢失（可采用确认或保留可复制内容，最终机制待 UI 验收）。
- **浮层不可用**：确认模式必须以复制/可恢复结果的通知安全降级，**禁止无提示直接打字**；保留可取回的识别文本，且不会切换为“自动写入”。
- **剪贴板**：尊重 `restore_clip` 既有选项。当前确认浮层会复制结果到剪贴板，因此应提示该行为；不能因修改 UI 让自动输入模式永久覆盖用户原剪贴板。用户手动复制时，以用户最新复制操作为准。

## 6. 快捷键与录音模式

- 沿用当前默认 Caps Lock、X2（实际是否启用仍按用户设置），允许多个快捷键并存；避免新向导悄悄覆盖已有配置。
- 设置页保留快捷键捕获界面，显示设备类型、组合键、冲突/权限提示和“保存后何时生效”；不强迫用户理解底层键码。
- **长按模式**：按下触发录音，松开结束；短按触发阈值与按键补发策略按现有逻辑保留，需真实 Windows 键盘/鼠标测试。
- **单击模式**：第一次单击开始，第二次单击结束；明确显示录音中，避免用户忘记正在录音；允许安全取消。
- 更改快捷键期间不应误启动实际录音；捕获失效、权限不足时保留旧配置并提供恢复入口。
- 浮层关闭不等于关闭后台听写；完全退出必须停止录音/服务并清理资源。

## 7. 输出方式、热词和 AI 的入口安排

### 控制中心「通用与交互」
保留现有快捷键设置、长按/单击、浮层开关、直接写入/确认后写入、确认框停留方式、粘贴兼容、自动回车等。分成“常用设置”和可展开“高级兼容性”，不删除现有参数。

### 「热词与替换规则」
保持独立导航和 `hot.txt` / `hot-rule.txt` 编辑入口；用户保存后明确下一次识别生效。不要在录音胶囊里增加复杂热词编辑器。诊断时可查看最终文本与本地规则处理的来源。

### 「AI 润色与角色」
沿用现有可选 AI 档案、角色配置和输出位置；正常离线输入不强制配置 API。仅实际匹配/启用的角色才进入 AI 处理状态；AI 中断或失败时告知原识别文本仍可用，不能自动丢弃；不重复触发或在用户编辑期间覆盖内容。

## 8. 异常/隐私/测试要点

| 场景 | 目标体验 |
| --- | --- |
| ASR 服务存在但未就绪 | 快捷键不能启动假录音；提示正在加载/无法使用 |
| 模型加载后 Worker 异常退出 | 状态刷新，下一次触发给出明确不可用原因 |
| 无麦克风、被占用或无系统权限 | 明确问题和打开 Windows 设置的说明 |
| 录音很短/没有可识别语音 | 非空误报、不向目标窗口写入随机文本 |
| 输入目标消失或获得错误焦点 | 不粘贴到其他程序，保持文本供复制 |
| 浮层被遮挡或创建失败 | 显式安全降级，不绕过确认模式 |
| AI 超时、断网、未配置 API | 退回原识别结果，离线功能继续可用 |
| 重复按键、连续识别、任务取消/晚到结果 | 不串回合、不重复上屏、不中断其他任务 |
| 自动关闭、编辑内容和剪贴板 | 编辑后不自动丢失，测试复制/恢复剪贴板 |
| 直接写入和应用兼容名单 | 校验真实 Windows 软件中的输入与自动回车，不能只靠 mock |
