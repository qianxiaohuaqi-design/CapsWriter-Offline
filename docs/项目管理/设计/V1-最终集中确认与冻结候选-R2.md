## 3. 首发范围：全部 C0 + 指定基础完善

### 3.1 C0 原有门禁全部保留

无模型 GUI、可信 SenseVoice 下载/校验/安全安装与真实加载、现有全部功能回归、真实状态、数据与密钥保护、Installer/Portable、基础官网、实际验收要求均保留。

以下原来有时被概括在 C1 中，但已经由既有 C0 用例规定，必须消歧：

- 配置导入：预检、变更范围确认、备份、读回和失败恢复，对应 `CF-03/CF-04`、G5。
- 热词/正则：非法规则阻止保存、外部修改冲突保护，对应 `CF-01`、G5。
- 输入目标、浮层文本、源媒体、源旁旧字幕、模型和个人数据的保护，不因体验增强延后而取消。
- 真实状态、故障后无假就绪与旧数据可恢复属于基础正确性。

### 3.2 原“建议同时纳入”的六项收敛到具体深度

| 项目 | 推荐首发深度与归属 | 不扩展为 |

| 转写任务持久化 | 纳入 C1 `FT-03`：恢复列表、保留完成结果、旧孤立运行任务标中断、单项从头重试 | 精确音频断点续写、专业编辑器 |

### 4.2 HTML 交互原型

- 输入事件同步保存编辑文字，后续重绘/切页往返不恢复成初始句子；编辑后即使改回原文，该回合仍保持已编辑状态。
- 向导保存最近步骤，跳过/切页后再次打开可恢复；明确完成后下次可重新开始。
- **原型仅在当前页面会话中恢复状态，真正刷新浏览器会重置。** 这不是 Windows 程序跨重启持久化的交付。
- 原型继续保持原有八项导航与外观，页面仍标注模拟，不执行真实模型下载、录音或粘贴。
- 验证：Node VM + 最小 DOM 桩执行实际原型脚本的 9 项针对性行为检查通过。Chromium 在当前执行环境因 `socket() failed: Operation not permitted` 未能启动，故浏览器视觉与 Windows 实机测试均未完成；没有把模拟检查升级为实机结论。

## 5. 冻结时应统一的工程与验收表述

### 5.1 后台三种动作分别验收（批准第二节后写入正式包）

| 动作 | 预期 | 必要证据 |
| --- | --- | --- |
| 关闭控制中心窗口，后台保留 | 模型下载继续 | 已知可控网络条件下关闭前后下载实际字节增加；重开接回相同 download_id 与真实阶段，不能只检查托盘图标 |
| 关闭窗口且存在转写任务 | 经实测可后台则继续；否则提示后等待或安全停止 | 原任务、状态和产物可追踪，无假继续、无覆盖；取消尚未确认时不提前报已停止 |
| 完全退出应用 | 下载安全暂停；转写到安全边界；持久化恢复信息并停止归属进程 | 下次启动可恢复任务状态；下载续传还需来源身份/Range 校验，不支持则从头获取 |

R1 中“后台不可继续则安全退出”不能在批准后的“模型下载必须继续”路径里充当 PASS。它仍可用于转写的明确降级路径，以及应用完全退出处理。

### 5.2 数据路径与内部实现交给 Codex 按事实确定

冻结的是行为：程序资源与个人数据分离、Portable 可随目录迁移、旧目录原位兼容、迁移先预览/备份/复制验证且默认保留原件。

具体有效路径、优先级、IPC、SQLite 或原子文件在 B0 读取本机 M1-A 后由 Codex 选定并记录。常规兼容实现无需再向用户逐项征求；如果将搬迁/覆盖用户真实目录，则遵守已批准的迁移确认流程。不得凭旧远端文档新建第二套路径系统。

### 5.3 官网 G7 分为技术交付与公开分发证据

- **G7-T 技术交付检查**：本地静态站、真实构建元数据、真实产品截图、许可/隐私说明、未发布按钮禁用可验收。
- **G7-P 公开分发检查**：用户授权实际发布之后，核验 EXE/ZIP 的公开可访问性、版本、大小、SHA-256、签名状态和官网链接一致，才启用下载并记通过。
- G7-P 未执行时记 `NOT_RUN—待发布授权/公开验证`。可交付技术包供用户验收，但不能声称“G0–G8 公开发布门禁全部通过”。
- 不因 G7-P 尚待授权而反复返工已通过的本地网站，也不为通过门禁擅自创建公开 Release。

### 5.4 保留现有内核与工作区

保留 NiceGUI/PyWebView、ASR EngineFactory、现有 Worker 和成熟功能；优先复用真实 `ready_event`、当前实例身份与失效校验，增加必要协调层即可。

本地 `e7cc1e2`、W01 和原 11 项未提交改动仍是待本机核验事实。最终 B0 先保护并识别已做工作，不重复实施 M1-A，不使用 `reset/clean/pull` 清洗工作区，不上传私人配置、Key、模型、录音或未知资料。
