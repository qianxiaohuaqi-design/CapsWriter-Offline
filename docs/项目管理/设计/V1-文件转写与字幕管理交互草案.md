## 1. 真实代码核对（远端 master d122f845）

- `web_gui/app.py`「字幕转写」已实现：单文件选择、批量添加/移除、逐个转写、总进度条/阶段文本、运行时取消、输出格式开关、查看结果/全文/打开文件、TXT+JSON 重建 SRT、最近输出历史和删除确认。
- `web_gui/transcription_service.py` 复用 `FileTranscriber` 与 `ResultHandler`，有 `checking/sending/receiving/saving/done/error` 进度事件，调用 FFmpeg 抽音频、服务端 ASR，生成配置允许的 TXT/SRT/JSON/merge.txt。GUI 输出最终移动到 `web_gui/outputs/<safe_stem>_<timestamp>` 下。
- `web_gui/transcription_history.py` 依据输出文件夹列历史，未提供可靠的持久化**任务状态**。GUI `batch_queue['files']` 是页面内存队列，不能把页面运行时队列等同于可跨重启恢复的任务系统。
- `core/client/manager/file_runner.py` 仍提供多文件顺序处理与文本/SRT 修正的旧文件入口，应保护兼容；当前 GUI 已有独立调用入口，不宜再新建 ASR 实现。
- `core/client/transcribe/result_handler.py` 在原始文件相邻位置写 `.txt/.json/.srt/.merge.txt` 后由 GUI 搬迁输出；需要核实存在同名文件、异常中途落盘、可取消任务的原子性和删除边界，不能在 V1 强制覆盖已有文件。
- `config_client.py` 当前 `file_save_srt=False`、`file_save_txt=True`、`file_save_json=True`、`file_save_merge=False`；历史说明文档与 GUI 设置内读取默认值存在差异，设计/实施需统一真实配置读取和文案。
- `MediaTool` 优先查找项目内置 FFmpeg/ffprobe，也可寻找 PATH；缺少 ffprobe 影响准确计算进度，不代表 FFmpeg 完全不可用。
- 本轮仅读取远端源码与文档，**没有运行真实转写、视频、字幕对齐、取消、页面重启测试**。旧文档的“几乎所有格式”“理论上无限时长”“准确时间戳”均不作为全面实测保证。

## 2. V1 页面信息架构（待确认）

保留左侧「字幕转写」入口和现有浅/深色卡片系统；右侧从上到下：

1. **文件添加区**：选择单文件、批量选择文件，支持窗口级拖入（需验证 NiceGUI/PyWebView 的本机路径/权限能力，不可先宣称已有）。显示文件名、时长/大小（实际可读时）、可否处理、已选模型；用户可移除待开始的文件。
2. **任务列表**：每个输入文件独立展示排队/检查中/音频提取与发送/识别中/输出生成/完成/失败/取消等状态；一个活动 ASR 文件任务顺序执行，其余排队，避免与实时听写无控制地争用资源。
3. **当前任务详情**：阶段、实际获得的工作进度和事件时间；没有 ffprobe/时间戳时明确“无法估算百分比”而不是制造精确 ETA；操作为取消当前项/查看问题。
4. **输出格式与设置**：用户按任务或以用户既有配置选择 TXT、JSON、SRT、merge.txt；保存前校验要求。高级分段和相关 ASR/语言设置继续指向现有入口，不复制两套设置。
5. **结果与字幕修复**：完成任务提供“查看全文、打开输出目录、打开 TXT/JSON/SRT、复制、根据已编辑 TXT 重建 SRT”；编辑 TXT 优先打开本地文件编辑器，V1 不必重做专业字幕时间轴编辑器。
6. **历史输出**：与既有输出目录及已完成记录关联；不混淆“已完成任务”与“输出文件仍在”；清除列表、删除应用创建的输出和删除原始媒体是不同操作。

旧用户不会因为新 UI 而丢失原有热词、语言、识别模型、转写设置与文件入口；无模型时历史及设置仍可浏览。

## 3. 单文件与批量主流程

**单文件**：本地选择 → 预检文件存在/可读、模型真实就绪、FFmpeg、磁盘/权限 → 加入队列并允许开始 → 提取/发送音频 → ASR → 有效结果 → 按格式生成到独立暂存目录 → 校验最终产物 → 原子发布至应用管理的专属任务目录 → 显示完成结果与历史。任一步失败或取消，明确错误与可重试入口。

**批量**：一次选择多个文件 → 预览任务清单 → 可移除待处理项/调整顺序（是否首版支持拖拽排序可降级为上移/下移） → 开始后顺序处理 → 每项独立结果与状态 → 失败默认继续后续任务并保留单项重试 → 顶部展示“成功 X / 失败 Y / 待处理 Z”，**不能所有任务结束就无条件显示全成功**。

**源媒体保护**：源文件只读，禁止更名、移动、覆盖或删除。输出不写回原媒体所在目录；旧 CLI 行为兼容需由 Codex 在实施中单独核对，并避免 V1 GUI 调用旧逻辑造成同名文件覆盖。若不修改旧 `ResultHandler` 就无法保护原文件旁同名结果，需先做受限输出工作目录/安全暂存层，不可在生产环境冒险。输出目录唯一 task ID，不能仅依赖秒级时间戳+同名文件防重。

## 4. 任务状态与取消

| 状态 | 可见提示 | 操作 |
| --- | --- | --- |
| waiting | 等待开始/排队中 | 移除/调整顺序 |
| checking | 检查文件、工具、模型与磁盘 | 取消 |
| extracting | 正在提取并发送音频 | 取消 |
| recognizing | 正在识别音频 | 取消，需正确关联服务端任务 |
| writing | 正在生成文件并校验 | 取消时遵守原子文件边界 |
| completed | 已完成，文件可查看 | 打开/复制/重做 |
| failed | 转写失败（展示阶段与脱敏原因） | 重试/诊断/跳过 |
| cancelled | 已取消（源文件未改变） | 重新开始 |
| interrupted | 上次异常退出，任务中断 | 核验现有结果/重新开始 |

状态属于**设计语义**，不要先强制写成新的状态枚举；须在 Codex 实施时与现有 GUI/ASR 任务协议映射和回归。原 GUI 的 percent 35～90 为基于音频时长的估算，不能当真实完成度保证；模型时长未知、长任务阶段应显示非确定进度。

- 取消：既有 `asyncio.Task.cancel()` 并不能凭自身证明服务器端停止了相关识别工作；需要真实任务 ID、异步进程/FFmpeg 清理、结果落盘竞态与晚到事件防护；状态只反映真实取消完成。
- 任务可恢复性：**排队清单、任务参数和已完成结果可持久化**，异常退出后重建视图；**正在进行的 ASR 不能无证据宣称从百分比断点继续**。V1 允许安全从文件开头重新转写，保留已成功产物，避免重复覆盖。
- 关闭 GUI 与托盘保留：若后台任务控制器真实独立于 GUI，则继续运行并可重连查看；若本机实现尚做不到，必须明确提示“关闭窗口将中断正在转写的任务”，让用户选择保留 GUI 或安全取消，**不可虚报后台继续**。
- 完全退出：保存清单/已完成结果，安全取消受影响任务；重新打开后可区分完成、未开始、异常中断。
- 同一源文件在不同模型、语言、参数下转写，作为独立 task_id；历史记录关联生成时的模型与选项，但不混入隐私凭据。

## 5. 输出格式与字幕重建

| 格式 | 用户用途 | 前置条件 |
| --- | --- | --- |
| TXT | 分行文字、可人工修改 | 有有效识别文本 |
| JSON | 时间戳/Token 等结构化结果 | 实际识别返回相应数据；不能虚报有字级时间戳 |
| SRT | 时间轴字幕 | 模型具备足够可靠的时间戳，或已安装并成功运行所需 ForcedAligner |
| merge.txt | 无分行全文 | 有有效识别文本 |

- 新用户界面建议默认 TXT + JSON；SRT 在时间戳能力得到确认时推荐开启；历史用户当前已保存的输出配置必须保留。最终默认组合等待产品总验收，不随意覆盖旧设置。
- 选择 SRT 但无时间戳/对齐模型时，应说明缺失及去模型中心安装辅助模型的入口，允许只导出 TXT；不能伪造准确字幕。
- “字幕修复”：从已完成结果选择 TXT + 匹配 JSON → 打开 TXT 编辑并保存 → 生成前预览目标 SRT 文件路径及同名覆盖风险 → 默认生成新版本/备份旧 SRT；如果 TXT 已改变且无法与原时间戳可靠匹配，要提示可能对齐不准。
- 原历史输出路径和 GUI 管理输出路径须保留读兼容；不强制迁移或删除旧记录。
- 文件打开/复制失败须可重试；输出没有成功持久化前不能显示“完成”。

## 6. 错误、隐私和回归

- **无模型/仅端口在线未就绪**：显示“模型尚未就绪”，可转模型中心；不得让用户等待无限转圈。
- **FFmpeg 缺失**：明确安装指引及实际检测路径；缺失 ffprobe 时只影响进度精度的情况须与 FFmpeg 缺失分开。
- **不支持的格式、文件损坏、无音轨、权限不足、磁盘已满**：单任务错误，队列中其他任务不受影响。
- **进程意外退出、WebSocket 断开、输出移动失败**：结果文件原子化、任务恢复并保留有价值的日志与可重试状态。
- **删除历史**：只能删除应用管理的输出目录，通过可靠路径归属校验（如 `Path.relative_to` + 不跟随不可信符号链接，避免 `str.startswith` 路径前缀误判），二次确认，源媒体绝不删除；私有文件路径不外传。
- **模型切换**：转写进行中不能被背景模型切换静默抢占，需排队或明确提示用户。
- **测试**：真机 Windows GUI 单/多文件、离线 ASR 与时间戳、编辑重建、重新启动、取消/超时、FFmpeg/ffprobe 缺失、同名文件、非 ASCII 路径、权限与磁盘不足、大文件、源文件 SHA 不变、旧 CLI 兼容等；自动化模拟通过不等于实机验证。

## 7. 待统一决定（非当前已冻结）

1. **任务列表独立常驻页面，还是在原“字幕转写”页面内分区？** 建议：保留一页，原有导航不变，任务列表放在添加文件区下方。
2. **关闭 GUI 后的转写任务**：建议尽可能让后台控制器随托盘运行，若改造成本或风险过高，V1 允许用明确阻止/确认关闭的方式降级；绝不伪装后台正常。
3. **字幕的专业编辑器**：V1 建议沿用 TXT 外部编辑 + JSON 重建，不新增复杂时间轴拖拽编辑。
4. **失败后的重试粒度**：建议从该文件开始重新处理，不承诺精确音频位置断点恢复；既有已成功结果保留。
5. **输出默认格式**：建议新装时 TXT + JSON，时间戳可用时提供 SRT 快捷启用；已有用户配置不变。
