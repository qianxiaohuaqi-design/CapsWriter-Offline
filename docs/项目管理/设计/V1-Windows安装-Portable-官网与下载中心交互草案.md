## 1. 发行范围与明确分工

V1 主要交付：
1. **Windows 标准安装版 EXE**：主推，不内置大型 ASR 模型权重。安装程序写入桌面应用与受许可的运行依赖；首次启动引导用户选择、下载、导入并校验模型。
2. **Windows Portable ZIP**：保留便携版，无传统系统安装，解压后运行独立启动程序；复用同一识别功能、模型管理与 GUI。首次没有模型时也能启动 GUI 并引导安装。明确其更新与数据目录策略。
3. **静态官网与下载中心**：桌面端既有品牌风格延续到网页（清爽排版、现有 Logo/色系、浅/深主题语言的视觉延伸），不重做桌面 UI。官网负责产品介绍、实际截图、下载安装指引、模型说明、FAQ、发布信息和权利声明。
4. **发布与验证流程**：构建、安装/便携验证、发行清单、SHA-256、许可与依赖检查、版本说明、发布审批、官网链接核验。

**V1 暂不主推**：预装 SenseVoice 的巨大 Full 包、macOS/Linux 安装程序、账号系统、云端上传/同步、付费下载站、复杂差分更新、应用商店发行。旧的 `CapsWriter-Full.zip` / `CapsWriter-Lite.zip` 是现有历史打包脚本产物命名，不代表这轮已交付的安装程序。

## 2. 现有代码/发行问题

- `make_releases.py` 目前是 Full/Lite ZIP 装配方案，会扁平拷贝 SenseVoice 文件，潜在破坏 `config_server.ModelPaths` 依赖的多级模型目录；其中的清理步骤会移除 `LICENSE`，与仓库 MIT 权利声明要求保留许可证不相容。
- `zip_release.py` 也是以 `dist/` ZIP 打包为主、排除较深层模型文件，不能直接作为新模型清单的完整发布流程；两份打包脚本不可不审查就同时用于生产。
- `create_shortcut.py` 使用绝对用户桌面路径、会生成 VBS/BAT 并可能改写启动文件，不适合泛用安装器的不同 Windows 账户；系统快捷方式应由安装器按实际用户安装模式创建。
- `build-client.spec` 偏向旧独立客户端构建，并非已验证的统一 GUI/ASR/托盘全产品安装版定义；主构建需要验证本地未跟踪 `build.spec`、运行依赖、FFmpeg、资源路径与许可证。
- `LICENSE` 实际存在（MIT，原作者版权），最终 ZIP/安装目录/官网须保留适用的版权与许可；第三方依赖、FFmpeg 和模型权重有各自分发条款，不能默认与主程序许可相同。
- 当前 `readme.md` 仍解释 Full/Lite 及代码覆盖更新，V1 正式发布后应与新安装器/Portable 的真实用户步骤同步；不可把历史 README 下载步骤直接作为 V1 已上线说明。

## 3. 安装版交互流程

### 3.1 安装步骤（软件包不含 ASR 权重）
1. 欢迎页：产品名、实际版本、发布者名称/签名状态、主要用途、版权/许可证入口；不把本产品误称为原项目官方发布者。
2. 安装模式：**建议默认“仅为当前用户安装”**（尽可能无需管理员权限）；全用户模式是否允许视实际权限与路径测试决定。遇到权限限制显示可理解原因，不暗中要求管理员权限。
3. 安装选项：目标程序目录（默认为当前用户可写的规范位置）、创建桌面快捷方式（用户可选）、开始菜单快捷方式；**开机启动默认关闭，须用户显式启用**。首次模型下载在应用中发生，不在安装器中强制下载。
4. 文件写入：展示真实进度、磁盘空间与错误；安装不捆绑未核实的模型或第三方程序，不删除现有数据/配置；遇到正在运行的 CapsWriter，提示关闭并保证受影响任务安全处理。
5. 完成页：可勾选立即启动；进入“无模型 GUI → 首次向导”或已有模型直接进入控制中心。即使网络不可用，也能打开程序并选择稍后配置。
6. 系统注册：卸载入口与真实版本/发布者/图标/程序路径一致；不写入不必要系统全局注册表项目、不私自更改默认输入法。

### 3.2 推荐技术方向（待整体工程冻结）
- **Inno Setup 作为 Windows 安装器首选候选**：与 PyInstaller onedir 构建产物配合，支持当前用户安装、快捷方式、升级/卸载入口。支持无管理员模式的条件由实际运行目录/子进程/权限联调验证；不能仅凭配置值判定产品可无提权运行。
- 使用明确的**单一构建清单**，将安装版与 Portable 的二进制版本、依赖、版权说明、资源和版本号关联到同一被验证的构建源；不复用会误删 LICENSE/模型目录的旧打包操作。
- 暂不采用复杂的系统服务、内核驱动或常驻后台提权；全局快捷键/剪贴板注入/托盘按用户会话权限运行，敏感系统权限由用户主动决定。
- 官方技术资料参考：Inno Setup 非管理安装 `https://jrsoftware.org/ishelp/topic_admininstallmode.htm`、`https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm`；Microsoft SmartScreen 开发者说明 `https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation`。这些材料是设计依据，不是本项目签名/安全已通过证据。

## 4. 数据目录与迁移：严格保护

- 安装版程序文件和用户数据、ASR 模型、热词、角色、私有 API 配置、历史、录音、转写结果、日志分离；大型模型位于非系统程序安装目录的适当可写用户位置。具体 Windows 路径与本机 M1-A `paths.py/catalog.py/status.py` 契约对齐后冻结，**此阶段不擅自改用户路径**。
- Portable 自带可配置的便携数据目录，尽可能保持解压目录内数据迁移能力；若文件夹无写入权限、放在 U 盘只读/程序目录受保护，提供明确恢复指引而不是静默写入别处。Portable 下的个人配置不得误随分发 ZIP 带出。
- 安装版升级、Portable 更换版本、从旧版 Portable 转标准安装版：先识别/预览已有数据与模型，备份并复制验证，再切换引用，不默认移动或删除旧目录；冲突不静默覆盖。
- 卸载程序默认**保留用户数据与已下载模型**；移除模型或私人数据是另一个需要主动勾选、明确范围、二次确认的动作；不能删除非应用拥有的自定义目录。重装可检测并恢复保留的资料。
- 生成公共发行包时须有构建前后隐私扫描：不能包含开发者私有 `private_config.json`、真实 API Key、热词个人内容、历史、录音、模型私有缓存、日志或本地用户路径。

## 5. Portable 用户流程

下载 ZIP → 核验来源/版本/哈希（有可用发行清单时）→ 解压到普通可写目录 → 双击 CapsWriter.exe → GUI 正常打开 → 有模型直接使用、无模型进入相同向导。Portable 不自动注册卸载入口，不在安装过程中要求系统管理员权限。

- Portable **不是**“完全不留任何操作系统痕迹”的保证，不应作此宣传；它仅指无需标准安装并保持便于迁移的文件结构。
- Portable ZIP 只包含一套运行所需程序/资源与相关权利声明；模型单独下载或导入。按用户可见目录说明哪些位置需要保留；覆盖升级前备份用户资料，确保老数据不会误覆盖。
- 源码运行模式仍保留开发者入口，但不列为普通用户第三个主下载按钮。
- 对本机托盘/FFmpeg/模型路径、Win10/11 支持范围、硬件后端应进行真实电脑测试后才标示官网兼容矩阵；不根据 README 旧截图推断“100%兼容”。

## 7. 静态官网技术路线

- 以轻量静态站点优先：语义化 HTML、CSS、极少 JS 或可静态构建框架；无需账号、后端数据库和实时遥测服务。内容源与发行元数据可版本化管理。
- 桌面产品配色、Logo、字体层级延续现有设计语言；根据网页特性做响应式适配与可访问性处理，不强迫网页复刻桌面 1120×740 的固定布局。
- 下载区从经过校验的版本清单/Release 元数据生成，确保 **同版号、同构建哈希、同实际下载链接**；动态“下载次数/评分/准确率”没有证据就不展示。
- 首版可以仅提供简体中文，英文界面/国际化可作为扩展（是否 V1 必需待总设计验收），不得把“英文版即将上线”当承诺。
- 官网不预置任何真实用户 API Key/音频/识别历史；静态构建和部署产物做敏感信息扫描。用户主动跳转 GitHub 时标示外部站点。
- 官网可展示已验证发行文件、校验值和源码链接，未来自动更新器与官网共用同一版本真值源。正式部署之前只在本地预览和测试。

## 8. 发布审核与安全合规门禁

1. **权利与许可证**：仓库 MIT LICENSE 原有版权声明完整保留，分发包包含合理的许可证材料；审查第三方 Python 依赖、FFmpeg 二进制的许可证和具体编译选项，以及 ASR 模型/模型数据的再分发权利。模型不内置不等于模型来源与许可证无需审查。
2. **源码/打包数据保护**：只从干净构建输入、受控白名单收集文件；特别防止 developer 私有配置、tokens、用户热词、录音与日志被打包；旧脚本的移动/删除/拍平不得直接作用在真实用户工作目录。
3. **构建一致性**：相同源码标识及构建配置生成 Installer 与 Portable；输出 SHA-256、文件大小、版本、支持的架构、可核验签名状态；干净 Windows VM 验证新装/升级/卸载/模型安装/重装不丢数据。**没有证据的数字签名不能在官网标为“已签名”。**
4. **SmartScreen 与签名**：优先评估受信任代码签名方案及成本/资格；即使合法签名，新二进制仍可能收到 SmartScreen 信誉警告。若尚未签名，网站必须如实展示，提供官方来源和哈希校验指引，不能教用户关闭防护或声称无警告。参考 `https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation`。
5. **版本与回滚**：更新器/官网/打包统一版本号及稳定/预览渠道，测试旧数据迁移和恢复；审核发布说明与实际文件。远端 GitHub Release 发布、网站部署和自动更新渠道上线须用户单独授权。
6. **证据层级**：“已规划 / 已编码 / 自动测试通过 / Windows 实机通过 / 用户验收通过 / 正式发布”分别记录，不可跃迁。正式 V1 用户验收集中在 Codex 完整技术交付之后。

## 9. V1 用户流程验收矩阵

- 首次无模型安装、选择以后再装、离线进入 GUI、下载/校验/加载真实就绪。
- 安装路径含中文/空格、普通用户无管理员权限、用户拒绝开机自启、安装中磁盘空间不足、安装重试。
- 相同版本 Installer/Portable 的常用功能等价；Portable 解压到可写目录/只读目录/移动目录/重新解压升级后的数据安全。
- 旧用户从 Full/Lite/源码/Portable 迁移，发现现有模型、配置、热词与角色，保留原字节，不擅自“清理遗留目录”。
- 软件升级、卸载、重装后模型/历史/录音/热词/私有配置不丢失；删除用户数据时明确范围并二次确认。
- 发行包不存在原作者私人数据或使用者密钥；MIT 及适用第三方许可齐备；模型路径与真实 ASR worker 读取一致。
- Windows Defender/SmartScreen 提示、代码签名状态、运行权限、主程序与 FFmpeg/ASR 依赖实机验证。
- 官网 Windows Installer/Portable 下载入口分别指向已验证真实文件，版本/哈希/日期/文件名准确；404、断链、未发布状态有合理展示。
- 网页移动端显示、中文文案、可访问性、隐私与许可证说明；网站不内置用户数据。
- 实际部署、发行、模型再分发、收费签名/域名等外部副作用均需单独授权。

## 10. 整体设计冻结前待统一确认

1. 标准安装器首选 Inno Setup，默认按**当前用户安装**，如确有需求再支持全用户安装；是否正式定案取决于现有二进制/快捷键的 Windows 实机测试。
2. 首页主下载项只有“Windows 标准安装 EXE（推荐）”与“Portable ZIP”；首发不提供预装模型 Full 包和 Windows 以外平台下载。
3. 轻量静态官网，尽量使用实际截图；GitHub Releases 作为初始实际文件分发真值来源，正式网站域名/托管与签名策略待发布审批。
4. 首版只提示检查更新还是支持完整一键升级，需结合 V1 更新安全验收决定；不能为了营销添加未实现按钮。
5. 不做默认开机自启；卸载默认保留用户模型和数据；在线 AI 与离线 ASR 的网络/隐私边界对外说明准确。
6. 网站语言范围、公开版本号及命名、下载文件清单、许可、签名、模型包最终源在完整设计审查时核定。
