# CapsWriter-Offline V1｜关键操作与跨页面状态契约 R1

> 2026-11-02｜**待用户整体评审的设计契约，未冻结，不是当前源码实现或向 Codex 授权实施**。作为 [V1 整体设计复审 R1](V1-整体设计复审与范围收敛-R1.md)、[八项导航 UI 规范 R1](V1-八项导航映射与关键UI状态规范-R1.md) 与 [HTML 状态原型 R1](prototypes/capswriter-v1-control-center-ui-r1.html) 的补充，配套 [结构化验收用例](V1-关键操作验收用例-R1.json)。
>
> **已确认的用户原则**：忠实保留既有 CapsWriter 控制中心外观和成熟功能；全部设计与工程路线集中完成并验收后，才**一次正式交接**本地 Codex 连续开发到 V1；用户最后集中验收。此处列出的状态名是**交互语义**，不要求 Codex复制成新的 Python 枚举，必须首先核对其本地未同步的 M1-A paths/catalog/status 与当前项目契约。

## 1. 跨页面共通规则（所有按钮必须满足）

1. **前置条件先校验**：权限、目标对象、模型真实运行状态、足够空间、下载可信清单、依赖与任务互斥；失败不启动部分副作用。
2. **一次操作一个 request_id**：提交后按钮显示“处理中”且不能重复提交，后台结果关联 request_id、用户会话、目标模型/文件/task_id。过期消息不得修改新一轮 UI。
3. **状态不是“过程必定成功”的承诺**：可用状态为 `idle → checking → running → succeeded`，失败、取消分别是 `failed`、`cancelling → cancelled`。进入取消态不代表系统工作已经停止；不可取消的原子提交阶段应禁用取消或标明安全等候。
4. **真假数据分离**：“文件存在”“完整性通过”“模型 Worker 当前实例就绪”“客户端可输入”是四个不同断言；不把端口/PID 直接等同于就绪。完整性未验证的传统模型可经兼容识别尝试加载，但必须如实标“内容未完整校验”。
5. **统一状态快照**：由模型安装/下载控制器、ASR 运行时、听写客户端、文件任务和配置存储分别提供可核实原始状态，在 GUI 顶栏、模型设置页、诊断页、托盘用同一聚合快照及更新时刻；失效快照必须回到“状态待确认”而不是沿用绿色已就绪。
6. **用户原始数据受保护**：手动安装模型、已有目录、个人配置/API Key、热词、历史、录音、日记、源媒体和旧字幕不因 UI 切换、升级或诊断而自动删除/覆盖。所有写入优先暂存+验证+原子提交；失败需有恢复证据。
7. **UI 反馈明确**：每个操作定义前置条件、loading 状态、成功结果、失败原因与重试条件、取消语义及影响到的原数据。未知进度使用不确定进度指示，不虚构 ETA/速度/成功率。
8. **外部副作用单独授权**：联网下载模型、向外部 AI API 发送文本、软件发布/推送/部署、自动更新、破坏性删除、真实服务重启等依实际用户动作或最终交接的权限边界授权；界面原型点击不执行上述操作。
9. **现有八项导航不变**；“语音识别与硬件”可显示为“模型中心”仍待用户确认。新增向导属于主内容区临时流程，不增第九项导航。原代码调用 `ui.dark_mode(value=False)`，现有可确认外观为浅色，深色需独立验证。
10. **测试证据分层**：交互示意、代码检查、自动化验证、真实 Windows 设备、用户验收五个层次分别记录，不用模拟完成代替生产状态。

## 2. 聚合状态与数据所有权

| 独立领域 | 事实来源/身份 | UI 可见状态 | 持久化规则 |
| --- | --- | --- | --- |
| 模型候选/安装 | 可信模型清单 + 文件及内容核验 + 变体 ID | 未安装 / 未验证 / 损坏 / 已验证 / 安装中 | 模型目录与已验证发布元数据；未经用户同意不迁移旧目录 |
| 下载任务 | download_id、来源版本/URL/ETag 或同等证明、总量与实际接收字节 | 排队 / 下载 / 暂停中 / 已暂停 / 校验 / 安装 / 失败 / 完成 | 安全暂存与任务元数据，可恢复时核验来源一致；仅一个活动下载 |
| 模型运行 | worker_instance_id、模型 ID、进程/协议握手、就绪事件、更新时间 | 未启动 / 加载中 / 就绪 / 失败 / 已失联 | 当前活动配置与 last_good_model 分开；不持久化虚假运行 ready |
| 语音输入 | dictation_turn_id、按键会话、目标窗口身份与剪贴板策略 | 待命 / 录音 / 识别 / 可选 AI 处理 / 待确认 / 输出尝试 / 失败 | 原识别文字与用户编辑后的可取回结果，遵守原隐私设置 |
| 字幕转写 | task_id、源媒体绝对规范化路径/输入哈希(适用时)、处理参数与产物目录 | 待处理 / 检查 / 提取 / 识别 / 写入 / 完成 / 失败 / 取消 / 中断 | 排队清单与完成记录；异常中断从文件起点重试，不假称断点转写 |
| 配置/热词 | revision_id、路径与源内容哈希、变更集合与校验结果 | 未修改 / 编辑中 / 校验中 / 保存 / 冲突 / 失败 | 保存前快照+原子写入+回退；保留手动修改与私有配置 |
| 服务/更新 | 真实进程归属、服务会话、安装渠道及经过核验的发行信息 | 未启动 / 运行中 / 故障 / 更新可用 / 安装中 | 更新前备份、程序与数据分离、失败可恢复，不能以旧 PID 认为就绪 |

**不变式**：
- `can_dictate = current_worker_ready && client_connected && hotkey_available && !blocking_transition`（逻辑示意；实际仍需麦克风采集权限和输入目标校验）。若临时下载**另一个**模型，原活动模型可继续听写。
- `download_completed` 不能直接推导 `installed_verified`，后者更不能推导 `worker_ready`。
- 对“切换模型”的成功判断必须以新 Worker 的就绪验证结束；失败回滚旧 Worker、配置与持久化的当前模型记录，且只有回滚成功才称“已恢复”。
- 源媒体只读，GUI 转写不得在源目录先写同名文件；已完成的任务输出和日志应区分“不再有源媒体”与“已成功生成文件”。
- 活动任务的“暂停/取消/停止/完全退出”是不同操作，不复用一个无差别 kill。
- 使用外部 AI API 时，向第三方发送的是用户明确启用功能的**相关文字**；不是“所有数据永久离线”。

## 3. 首次启动与向导（WF）

| ID / 用户动作 | 启用条件 | 执行中 | 成功 / 失败 / 取消 |
| --- | --- | --- | --- |
| WF-01 初次进入 | 新安装无可用模型，GUI 自身已启动 | 显示硬件检测与现有模型扫描，结果逐项更新 | 进入六步向导；硬件检测失败则显示保守值、允许手选；用户“稍后设置”返回八项原导航，不误报已就绪 |
| WF-02 从设置页重新进入 | GUI 正常可交互 | 恢复上次安全保存的向导步骤、重新核验模型/下载事实 | 已安装的步骤可跳过；如果模型变体/来源已经变化则重新校验；关闭向导不撤销已验证内容 |
| WF-03 选择候选模型 | 型号+真实变体+发布来源/许可/校验信息可展示 | 预检磁盘、后端、下载来源 | 只有可信且允许下载的候选开放“一键安装”；否则提供手动导入/说明；硬件推荐不可取代用户选项 |
| WF-04 完成向导 | 记录有效配置并能报告实际状态 | 检查 Worker/客户端/麦克风测试结果 | 只有真实可用才显示“可以开始听写”；跳过麦克风测试则标“未测试”；向导完成≠强行启动未知模型 |

## 4. 模型下载、安装与切换（MD）

| ID / 用户动作 | 前置条件 | 执行中 | 成功 / 失败 / 取消 |
| --- | --- | --- | --- |
| MD-01 点击下载 | 可信来源、版本/变体明确、许可可接受、磁盘可写且有余量；下载须由用户明确触发 | 分配 download_id，单活动下载；其他排队；展示实际字节/阶段 | 进入内容校验；断网/空间不足保留未污染的可恢复缓存；点击取消仅进入 cancelling，不立即显示 cancelled |
| MD-02 暂停与继续 | 来源协议及下载器支持安全续传 | 暂停记录已落盘字节；继续前核验来源版本、长度/ETag 或同等一致性 | 校验一致后续传；来源变化/不支持续传则从头重新获取，不拼接不可信字节；停止失败不能声称暂停完成 |
| MD-03 校验与安装 | 下载完成、可信哈希与预期文件布局齐全、目录安全 | 校验哈希→安全解压→安装至独立暂存目录→提交 | 完成后显示“已安装，尚未加载”；哈希/路径穿越/权限错误不能启用、不能覆盖 last_good；原子提交阶段不能强行取消造成半安装 |
| MD-04 首个模型启用 | 没有可用的活动模型；目标已校验 | 设置 pending_model→启动 Worker→等待真实就绪 | 就绪后更新 active_model/last_good；失败清除 pending，允许重试，不宣称已可听写 |
| MD-05 切换第二个模型 | 目标已安装并匹配可用后端；没有活动录音或转写中等不可中断任务 | 确认将暂时中断识别；必要时等待/明确中止；新模型加载中 | 成功后切换并写入配置；失败尝试恢复 last_good，若也失败显示“恢复失败”，保留诊断和旧文件、不写假成功 |
| MD-06 手动导入/修复 | 路径、模型身份/变体及文件权限可检查 | 预览来源/目标/冲突；安全临时复制和校验 | 用户主动确认后应用；未知布局/无校验材料显示“未完全验证”，不删旧模型/未知文件 |
| MD-07 卸载/清理模型 | V1 是否提供独立卸载入口待冻结；仅本程序管理且非使用中的模型 | 预览具体目录、大小与是否被任务引用，二次确认 | 仅删除已验证归属的对象；手动导入的未知资料默认只读。**不能因按钮在原型中存在就默认启用** |

## 5. 语音输入、确认浮层和在线 AI（DI/AI）

| ID / 用户动作 | 前置条件 | 执行中 | 成功 / 失败 / 取消 |
| --- | --- | --- | --- |
| DI-01 开始录音 | worker 真就绪、听写客户端与热键注册可用、麦克风权限真实可用；无其他活动 dictation_turn | 分配 turn_id；长按或单击开启、显示现有声波胶囊 | 松开/再点结束→识别中；麦克风失败、短录音无效或过时中间文本不能向当前输入框写随机文字 |
| DI-02 接收识别文本 | 回包 turn_id 匹配当前回合、非已取消/过期 | 本地热词/规则/格式化，必要时调用用户已启用的 AI | 直接写入则只对**已确认仍合法的目标窗口**执行输入尝试；确认模式保留完整文字供编辑/复制；不能仅凭模拟按键发送成功就宣称目标已经保存文本 |
| DI-03 用户编辑确认浮层 | 结果存在且属于当前回合 | 首次真实修改后永久暂停该回合自动关闭，手动写入/复制/关闭 | 焦点丢失仍保留内容；原目标窗口已不存在时禁用危险粘贴，允许复制；Esc 关闭不误取消其他回合；复制 ≠ 授权粘贴 |
| DI-04 浮层故障 | 用户选了“确认后写入”但浮层无法呈现/目标不可确认 | 显示明确错误和文本找回入口 | 不静默降级为直接打字；可安全保留、查看、复制识别文字；不能强制覆盖当前剪贴板的用户内容 |
| AI-01 启用在线润色/角色 | 对应 API 档案存在、功能显式启用，用户已了解文字外发边界 | 仅发送当前回合所需文字；处理中的版本/turn_id 防止晚到覆盖 | 成功显示处理结果；超时/余额不足/绑定失效可使用原识别结果，不把失败写成 ASR 失败；不得显示/导出 Key |
| AI-02 用户已经编辑且 AI 晚返回 | 编辑回合版本已改变 | 晚到结果应被丢弃或由用户显式选择采用 | 绝不覆盖用户编辑后的文字，也不能错误地贴到下一轮文本 |

## 6. 文件转写与字幕重建（FT）

| ID / 用户动作 | 前置条件 | 执行中 | 成功 / 失败 / 取消 |
| --- | --- | --- | --- |
| FT-01 添加文件并开始 | 源文件可读、FFmpeg 和当前 ASR 可用、输出目录可写、源媒体不被修改；每文件 task_id 独立 | 按文件检查→提取→识别→写入与校验，串行优先，避免实时听写资源抢占 | 按每文件独立成功/失败；任务总览是实际各状态数量。输出到任务专有暂存目录，校验后提交，不写到原媒体旁同名文件 |
| FT-02 取消当前转写 | 目标 task_id 仍活动，关联服务器/FFmpeg 子任务可识别 | 标记 cancelling，要求终止工作并等待真实确认，禁止晚到结果写入错误任务 | 取消确认后 cancelled，保留已完成其他任务和原始媒体；失败时明示终止未完全成功；写入提交阶段按安全边界处理 |
| FT-03 异常退出后恢复列表 | 有持久化任务与产物元数据 | 恢复排队和已完成/失败记录；旧 running 标 interrupted | 用户可单文件重试，默认从文件开头重做；不伪称从中断秒数或百分比继续；若后台控制器不存在则关闭 GUI 前明确提示中断影响 |
| FT-04 TXT+JSON 重建 SRT | 对应文件配对正确、有可信时间戳/对齐能力 | 读取用户编辑的 TXT，预览生成路径与旧 SRT 冲突 | 新 SRT 独立版本/旧文件备份；时间戳不足则说明限制，不伪造字级准确率；失败不损坏旧 SRT |

| ID / 用户动作 | 前置条件 | 执行中 | 成功 / 失败 / 取消 |
| --- | --- | --- | --- |

| CF-03 导入配置 | JSON 版本/字段类型/目标权限检查通过，变更范围和冲突已展示给用户 | 全量预检→当前配置备份→按可恢复事务写入→逐字段读回校验 | 成功提示真正应用项；中途失败时回滚全部已修改项并验证，无法回滚必须显式列出具体影响；API Key 不因导入缺失而被擅自删除 |
| DT-01 清空历史/日志/转写输出 | 用户明确选择**具体数据类型及路径归属**，需要预览和必要时二次确认 | 逐项检查文件归属/引用/符号链接，显示不能恢复风险 | 仅删除授权范围内的应用管理文件；源媒体、模型、录音、日记、配置不受“清空历史”牵连；部分失败需列明未删除项 |
| DT-02 AI API Key 修改 | 用户主动编辑明确档案 | 遮蔽输入、验证目标档案与保存位置，不通过普通日志和导出传播 | 保存成功才更新 UI；失败保留旧凭据，不声称已有系统级加密（目前旧远端是本地明文 JSON） |

## 8. 服务、退出、更新、卸载与官网（SV/UP）

| ID / 用户动作 | 前置条件 | 执行中 | 成功 / 失败 / 取消 |
| --- | --- | --- | --- |
| SV-01 启动缺失组件/重启 | 确认是本程序进程、目标服务真实缺失或异常、无冲突任务或用户已确认影响 | 最小范围启动/重启→新实例握手→验证真实 Worker/客户端状态 | 新实例真的 ready 才显示可用；只拉起 PID 或端口仍可能加载失败；错误含脱敏诊断；不能误杀无关 6016/6017 进程 |
| SV-02 关闭 GUI | 能确认托盘/后台控制器的实际所有权及活动任务处理方案 | 只关闭窗口、不无授权关闭 ASR/热键；需要时提示未完成任务 | 后台实际存活才显示“任务继续”，否则明确提示 GUI 关闭会中断且提供等待或安全取消 |
| SV-03 完全退出 | 用户明确从托盘或诊断页选择，并了解录音/下载/转写影响 | 停止新任务；模型下载安全暂停并写元数据；转写结束/中止并持久化；再释放进程与热键 | 退出后不遗留识别服务；下次启动可查恢复项。超时/部分停止失败应明确记录，不能杀无关 PID |
| UP-01 检查软件更新 | 用户主动点击或曾显式启用定期检查，联网来源已确认 | 获取发布清单，按安装版/Portable 渠道匹配，验证版本与来源 | 成功显示实际版本/说明/可信下载地址；无网络提示无法检查而非“已是最新版”，不自动执行升级 |
| UP-02 进行安全手动升级 | 用户确认下载和安装，活动任务已安全暂停/完成，发行签名/校验/许可可信 | 备份现有设置→获取已签/已校验的真实发行包→交由独立安装器更新→重启后校验 | 失败保留旧版恢复能力和用户数据；不要求 V1 具备静默自升级/差分回滚 |
| UP-03 卸载或重装 | 来自安装器明确用户选择；程序/数据目录和归属已核实 | 先安全停止任务，仅移除程序管理的文件、快捷方式和卸载项 | **默认保留模型和个人数据**；删除个人数据要单独主动选择+二次确认，不删除自定义未知文件。Portable 提供手动移除说明 |
| UP-04 官网发布文件 | 有实际经核实的 Installer/Portable 产物、版本、架构、文件大小、SHA-256、许可/签名状态 | 网站静态内容引用同版真实 Release 文件与文档 | 真实文件可用才启用下载按钮；未发布显示“尚未发布”，不虚构下载地址；正式公开部署另行获用户授权 |

## 9. 并发保护与资源冲突（必须在工程方案中落实）

| 活动任务 | 新操作 | 默认策略 | 原因 |
| --- | --- | --- | --- |
| A 模型正常听写 | 后台下载 B 模型 | **允许**，但共享磁盘/网络需节流 | 下载不代表切换，不中断 A |
| 正在录音/识别 | 切换当前 ASR 模型或重启 ASR | **等待或要求用户明确确认中断** | 防止丢失当前回合 |
| 正在文件转写 | 切换模型/重启 ASR/软件升级 | **等待或明确取消任务** | 避免任务使用的 Worker 意外失效 |
| 正在文件转写 | 用户发起普通听写 | **优先保障听写**；如果模型运行时不支持并发，文件任务排队/暂停在安全边界 | 不让批量转写使日常输入不可用；实际调度以真实能力为准 |
| 模型正在校验/解压/提交 | 取消下载或关闭程序 | 在**原子安全边界**停止/继续，不强行杀进程 | 防止半安装与损坏 |
| 配置事务正在写入 | 保存热词/再次导入配置 | 拒绝重复操作或进入有界队列 | 防止多个写入互相覆盖 |
| 任何未完成的数据写入 | 删除数据/卸载/更新 | **阻止直到可安全停止并完成确认** | 防止不可逆数据丢失 |
| 仅 GUI 关闭但托盘正常运行 | 查看下载/转写是否继续 | 必须检查实际独立后台任务控制器 | 内存队列不能假报后台继续 |
| GUI 多个页同时刷新状态 | worker 重启/结果异步返回 | 只接受当前实例有效且版本更新的快照 | 避免旧成功状态覆盖新错误 |

建议工程实现中明确四类协调资源：模型与下载目录写锁、ASR/Worker 切换门禁、文件任务队列、配置原子事务。不强制创建全局超大互斥锁，也不让 UI 主线程等待漫长操作。

## 10. 异常到 UI 处理的标准映射

- **校验失败**：显示“文件完整性不符合预期”，提供重新下载/选择可信来源，拒绝启用受损模型。
- **模型无完整校验来源但已存在**：保留原目录、显示“文件存在但完整性尚未核验”，允许在安全边界内尝试旧版兼容加载，不能删。
- **进程运行但模型未就绪**：显示“服务已启动，识别模型尚未就绪”，只提供真实可行的查看/重试。
- **AI 超时/余额不足**：显示“AI 处理失败，仍可使用原始识别结果”，不吞掉输入文本。
- **用户编辑后浮层失焦**：不恢复自动关闭倒计时，保留当前修改内容。
- **转写取消中**：显示“正在取消”，收到服务端/子进程完成证明后才置为“已取消”；源音视频不变。
- **配置导入部分失败**：列出回滚结果或明确哪些项未能恢复，不能只通知“导入失败”后不告诉用户哪些设置变了。
- **文件清理或卸载选择删除**：展示实际目录和对象范围、保留项及不可恢复性；用户取消则全部不改变。
- **窗口关闭时后台无法保证继续**：显示明确提示并提供“返回等待/安全停止后关闭”，不得保留一个假后台进度。
- **检查更新断网**：显示“暂时无法检查更新”和上次核验时间，不假装最新版。

## 11. 冻结前的交互测试和设计验收门槛

随附 JSON 中的 `cases` 是**设计验收用例**，不是本机已运行的单元测试。用户确认整体方案之后，Codex 应将它们映射到适合现有技术栈的自动化和真实 Windows 测试，不要求重造项目既有的测试框架。

- 各操作成功、失败、取消、重试后状态与输入/输出数据一致；断开 WebSocket、无网络、磁盘满、权限不足、重复触发、旧 request_id、模糊进度都需要覆盖。
- 历史模型与私有数据哈希不变；模型下载和 GUI 转写相互独立；第二模型切换失败能恢复旧模型且 UI 无假就绪。
- 真实麦克风、IME、焦点恢复、桌面快捷键、托盘、不同 DPI、超长字幕转写、实际安装/卸载需在 Windows 实机验收；Mock 不算这些通过。
- 旧 M1-A `e7cc1e2` 只是用户转述的本地开发回执，最终 Codex 需先核对其真实本地分支与未提交 11 项改动，不以本 GitHub 文档分支替换本机源码。
- **默认方案仍待用户整体确认**：例如“语音识别与硬件”是否改名“模型中心”、C1 是否全部纳入 V1、实际深色主题是否纳入，以及状态机实现细节。任何设计细节不自动视为用户已冻结。
