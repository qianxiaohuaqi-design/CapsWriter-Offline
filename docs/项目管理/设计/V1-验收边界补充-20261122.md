## 2. 六项冻结边界与本地检查

### 2.1 首次设置意图独立于模型运行状态

关联：`WF-01`、`WF-02`、`MD-04`、`MD-05`、`WF-03`；冻结总包 §3.1。

| 隔离场景 | 必须观察到的行为 |
| --- | --- |
| 从未设置且没有默认模型 | 六步向导可打开，可跳过；常规页面可用 |
| 已跳过或中断向导 | 常规界面有“继续设置”入口；重开恢复最近步骤并核对实际任务 |
| 已有模型正在加载 | 常规界面显示加载，不重新认定为首次用户 |
| 已有模型文件缺失或加载失败 | 保留默认选择与旧配置，提供修复/重试；GUI、历史、配置和诊断可访问 |
| A 是既有默认模型，B 下载中；A 此时失败，B 随后下载完成 | 默认仍是 A；B 仅显示已安装，未经确认不切换 |
| 首次明确选择候选并加载成功 | 当前目标 Worker 真正就绪后才提交默认模型；下载完成、文件存在或端口开放均不够 |
| 旧手动路径与 GPU 偏好 | 失败回滚恢复原实际配置，不强行改为目录清单默认路径或 CPU |
| 切换事务在 selection 文件产生前中断 | ASR 拒绝使用不完整配置；GUI 保持可打开，并能恢复原事务 |

新用户可选择本地已准备好的模型目录。导入只记录经过用户确认的路径，不改原文件。没有匹配的可信哈希时明确标“手动模型，尚未校验”；随后仍需实际 Worker 加载。外部手动目录不因 Portable 移动而被偷偷搬迁。

### 2.2 听写与长文件转写共享引擎

关联：`DI-01`、`FT-01`、`FT-02`；冻结总包 §3.2。

至少使用一个足以覆盖多个处理片段的公开或授权音频，在真实 Windows 上检查以下顺序：

1. 听写正在录音时排入文件任务，观察新文件不会抢在当前听写前启动。
2. 文件正在推理时按下听写快捷键，观察明确的忙碌/等待提示与可继续操作的入口；不能出现虚假的录音状态或无提示丢失操作。
3. 到达实际安全边界后重新听写，确认系统恢复可用；不得仅依据固定延迟推测边界已经到达。
4. 文件运行中请求安全停止，检查“正在停止”保持到 Worker/所属进程真实确认；旧片段的迟到事件不能把下一次尝试改回运行或完成。

检查真实引擎的处理粒度。规格不要求强杀正在执行的未知推理，也不承诺即时抢占；安全边界、忙碌提示和恢复能力必须与实际行为一致。

### 2.3 任务重试、attempt 与重开恢复

关联：`FT-01`、`FT-03`、`FT-05`；冻结总包 §3.3。

准备源音频及同名旧 TXT/JSON/SRT，先记录文件哈希，再分别执行成功、失败、取消与重试。每次尝试使用独立的产物目录；源媒体、源旁旧文件、前次完成产物保持原哈希。

- 重试沿用原模型、语言和处理参数。原模型不可用，或源文件已移动/内容变化时，显示原因并等待重新选择，不能悄悄改用当前其他模型。
- task ID 稳定，attempt ID 每次不同。连续点击重试不能生成两个并发尝试。
- 旧 attempt 的进度、完成和取消事件不能覆盖当前 attempt。新结果核验成功后才切换结果指针，失败时仍保留前次成功结果。
- 关闭 GUI 后重开，应先连接仍存活的后台 owner，并看到同一 task/attempt；只有确认不存在存活所属任务的旧运行记录才能标记中断。
- 应用完整退出或意外终止后，任务列表与完成结果仍可恢复。中断文件的重试从文件开头处理，不用进度条恢复来宣称精确音频断点续转写。

故障注入使用隔离测试进程和目录，不终止用户现役任务。持久化 JSON 存在只能证明记录保存，还需核对真实进程归属、任务状态与产物。

### 2.4 六步向导与后台入口

关联：`WF-02`、`MD-01`、`SV-02`、`SV-03`；冻结总包 §3.4。

六步结构保留，自动硬件检测、下载校验与安全安装的衔接减少重复确认。下载确认前展示核验过的文件大小、所需空间、保存目录、来源与模型许可。检测失败可继续手动选择；未测试麦克风不能显示为已通过。快捷键预填既有设置，完成页说明开始听写的实际操作。

后台需要分三种动作观察：

| 动作 | 必须保留的语义与证据 |
| --- | --- |
| 关闭窗口，应用后台保留 | 模型下载继续；在可控网络下记录关闭前后实际字节增加；重开后 download ID 不变 |
| 关闭窗口且文件任务运行中 | 真实独立后台可继续则接回同一任务；否则明确提示等待或安全停止，不能假称已在后台运行 |
| 完全退出应用 | 下载安全暂停，转写到安全边界并保存任务；等真实停止确认后结束所属进程，下次启动重新核对恢复条件 |

`SV-02` 的旧措辞“托盘运行或安全退出”已按批准后的承诺消歧：安全退出不能算“关闭窗口后模型下载继续”通过。也不能以托盘图标存在或端口可连接替代下载字节和任务归属证据。

首次安全关闭窗口只说明一次托盘与重开入口，后续不反复打扰。快捷方式和托盘应打开既有控制中心，不产生重复 GUI、下载管理器或任务。托盘启动失败时保留可访问控制入口。A 已就绪与 B 下载中应能同时显示，不能将下载 B 误报为整个系统不可用。

### 2.5 提前验证最小 Windows 包

关联：`WF-03`、`UP-02`；冻结总包 §3.5。

在具备 Windows 构建环境的最早阶段，先制作最小 PyInstaller 包，检查无模型启动、GUI/向导/修复入口、程序资源和可写数据路径、后台归属及重开行为。准备好可信模型后，用短公开音频确认打包运行时真正加载并识别；源码解释器能运行不等于包内依赖齐全。

若之前开发环境无法运行 Windows，本地接续先补此最小包检查，再完成完整 EXE 安装版与 Portable 验收；据实记录执行时间，不把后补测试写成此前已完成。

完整 B4/G6 仍须覆盖当前用户安装、干净 Win10/Win11、非默认安装路径、依赖与 FFmpeg、Portable 目录移动、同渠道升级及卸载默认保留数据。移动 Portable 后，受管理模型应依据新模型根定位；显式外部手动路径若不再存在，应明确提示修复。模型、录音、个人配置、API Key 和未知私有资料不能混入发行包。

### 2.6 唯一交接与本地已有工作保护

关联：`UP-02` 的交接子场景；冻结总包 §3.6。

恢复顺序是 [当前交接](../当前交接.md) → [冻结实施总包](V1-设计冻结与实施总包-20261122.md) → 绑定实际 SHA 的源码与回执。按阶段读取必要细则，旧 CHANGELOG 和历史任务只供核查；不重启七组设计确认或逐模块反复派工。

本地先记录实际分支、HEAD、暂存/工作区状态，核实用户报告的 `e7cc1e2` 与原 11 项修改，尤其保留未跟踪 `build.spec`。在独立 worktree 拉取并运行新分支，比较 M1-A 已有路径/模型/状态能力后再按语义合并。不能用 reset/clean/pull 清理旧工作区，不能把未取得本地代码说成其工作不存在。

最终交接词必须提供唯一开发分支、完整 commit SHA、启动/测试/构建入口、已执行证据和明确未执行项。源码上传授权与公开 Release/官网部署分开；本轮授权范围内的开发、隔离测试和源码交付可连续完成。

## 3. 网站与分发的证据边界

`UP-04` 明确区分 G7-T 与 G7-P。G7-T 检查静态源码、真实产品图片和真实构建信息；G7-P 需要公开分发授权及真实可访问的制品，逐项核对版本、文件名、架构、大小、SHA-256 和签名状态。未发布或未验证的下载按钮保持禁用。网站源码存在、截图漂亮或本地链接可点，都不能推出公开发布门禁已全部通过。

## 4. 本地回执最小记录

建议每条主用例下仅记录发生的子场景，格式为：

```text
用例/子场景：例如 SV-02 / download_progress_after_window_close
代码：完整 commit SHA；如有本地修改，列出补丁/提交及实际测试版本
环境：Windows 版本、Python/打包运行时、关键依赖、模型 ID 与校验值
动作：实际执行的步骤或命令
观察：实际字节、进程归属、任务 ID、截图/日志或文件哈希
结果：按实际情况填写 PASS / FAIL / NOT_RUN
限制：本条没有覆盖的设备、输入模式或故障条件
```

测试日志不包含私人 API Key、原始个人录音或不必要的历史文本。使用公开固定音频时记录来源与哈希；需要用户自己的声音或现役输入程序验证时，由本地环境执行并仅保存必要的脱敏结果。
