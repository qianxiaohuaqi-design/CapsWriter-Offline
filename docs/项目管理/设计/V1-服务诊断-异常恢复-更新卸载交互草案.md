## 一、现状代码证据（只读检查：master@d122f845）

- `run_app.py` 统一拉起 ASR 服务、快捷键听写客户端、GUI 与托盘，带重复启动检查；GUI 关闭与完整退出依赖具体启动器与进程管理，**现有行为不可仅凭函数名判定所有路径正确**。
- `web_gui/process_manager.py` 实现进程/PID/端口检查、启动缺失组件、重启、完全退出、日志扫描，`get_health_status()` **将 `model_loaded` 错误设为 `server_alive`**，端口 6016 在线不足以证明模型完成加载；某些停止操作会通过进程遍历/端口 PID 寻找并停止进程，需防止误杀无关进程及旧 PID。
- `web_gui/control_tray.py` 提供打开控制中心、启动缺失组件、重启听写、查看日志目录、完全退出；托盘提示目前主要依据 server/client PID 生存，尚不是真实 ASR Worker 就绪证据。还有 `core/ui/tray.py` 旧托盘体系，需要实施时核对所有入口、避免重复托盘或退出冲突。

## 二、导航与页面结构

保持侧边栏「服务与诊断」，不重建全局导航。右侧自上而下：

1. **当前可用性主卡**：用普通语言显示“可以开始听写 / 正在准备 / 暂不可用”，与首页、托盘、模型中心共用真实状态快照；明确给出当前模型名称、识别/客户端/麦克风前提和一个最有用的主操作。
2. **组件健康详情**：ASR 主服务（协议连接）、ASR Worker/模型真正加载状态、快捷键客户端、控制中心、托盘/后台任务。高级信息（PID、端口、最近事件、运行版本、诊断 ID）折叠展示，普通用户不被技术细节淹没。
3. **故障诊断与恢复**：显示最后失败阶段、精简错误、影响范围和一项首选修复。允许手动展开日志和下一步建议；不能把旧日志中的 ERROR 当成当前一定发生的错误。
4. **服务操作**：启动缺失组件、重试加载、重启听写客户端、重启 ASR、完全退出；每项显示影响范围和是否会中断当前听写/文件转写/模型下载。
5. **软件维护**：当前安装版本/渠道、查看发布说明、手动检查更新、更新准备/待安装/失败恢复、更新设置。Portable 用户与安装版显示匹配本渠道的更新路径。
6. **诊断资料**：打开本地日志、按时间范围预览旧日志清理、生成可检查的脱敏诊断包（用户明确选择后才打包/分享）。不能自动上传私有日志。

“模型还未安装”时首页/诊断页面仍可打开，直接提供「去模型中心」；“模型加载中”与“已安装但未加载”分开呈现。

## 三、运行状态真值契约

分别建模：
- **安装状态**：未安装 / 下载中 / 待校验 / 已验证 / 部分缺失 / 损坏与不兼容；以已核验的本机 M1-A 模型清单和状态 API 为准。
- **服务状态**：未启动 / 启动中 / 可通信 / 异常停止；不可把端口开放与特定 CapsWriter 实例身份画等号。
- **Worker 状态**：未加载 / 加载中 / 已就绪 / 加载失败 / 退出 / 状态过期；必须与当前进程、会话/启动版本绑定并读取可信加载完成信号，不复用旧 worker 的“ready”。
- **客户端状态**：未启动 / 启动中 / 已连接 / 连接断开 / 快捷键不可用，需区分进程在线与功能可用。
- **整体可用性**：“可以听写”只有模型真实就绪、识别连接和热键客户端符合条件，才能显示绿色可用；历史、设置、模型下载等非听写功能不要求该状态。

四处展示（顶栏、模型中心、服务诊断、托盘）使用同一状态源与更新时间/失效策略，不各自根据 6016 或 PID 拼状态。自动刷新时不能闪烁或把上一次成功状态误延续到进程重启后。

## 四、异常恢复设计

| 故障 | 用户主文案 | 推荐操作 | 保护规则 |
| --- | --- | --- | --- |
| 未安装模型 | 还没有可用的语音模型 | 打开模型中心 | GUI 与非听写功能仍可用 |
| 文件不完整/校验失败 | 模型文件需要修复 | 查看缺失内容、重新下载/导入 | 不覆盖可用旧模型 |
| 模型仍在加载 | 正在准备语音识别 | 查看状态 | 不能显示“已就绪” |
| Worker 加载失败/退出 | 语音识别暂不可用 | 查看原因、重试加载 | 清除旧“就绪”标记 |
| 听写客户端掉线 | 快捷键暂时无法使用 | 恢复客户端 | 不无故重启全部服务 |
| 麦克风被占用/无权限 | 无法访问麦克风 | 查看设备及权限说明 | 不破坏配置 |
| FFmpeg 缺失 | 文件转写暂不可用 | 查看安装说明 | 日常听写可继续（若不依赖 FFmpeg） |
| 下载/模型校验失败 | 下载或校验未完成 | 继续/重新获取 | 保留可恢复下载和旧模型 |
| 服务在使用中 | 正在听写或转写 | 等待完成/确认中断 | 不静默杀进程 |
| 未知错误 | 本次操作未成功 | 查看脱敏诊断 | 有界重试、不无限循环 |

恢复按“最小受影响组件”优先；自动重试必须有次数/退避和停止条件，避免重复弹窗与崩溃循环。每个动作统一防重复点击与并发状态，重启/取消引入请求身份和结果确认，不能仅凭拉起子进程成功就说整个服务恢复。

## 五、托盘与关闭语义

- **关闭控制中心窗口**：默认保持听写服务和托盘（前提是产品确实已建立可靠后台所有权），不是完全退出；用户可在托盘重开。
- **完全退出 CapsWriter**：停止 UI、快捷键客户端、ASR 与由本程序管理的后台任务，明确提示“听写将停止”；下载应有界安全暂停并保留可恢复状态，文件转写应等待/取消并保留已完成结果，未完成任务标记中断。不能结束无关进程。
- **重启 ASR/切换模型/更新应用**：如有活动录音、字幕转写或模型下载，应先提示影响，能无损等待则等；危险操作需用户明确选择，不悄悄停止长任务。
- **托盘异常不可用**：不能把“关闭窗口后仍可后台运行”作为绝对保证；程序应明确展示可用的替代方案（例如保留窗口/最小化）并恢复关闭行为。托盘只有一个可信所有者，避免重复图标。
- **状态文案**：模型加载完成且客户端联通才能显示“听写就绪”；只看 PID 的状态要写“进程运行中，模型状态待确认”。

## 六、软件更新交互（V1 目标，不等于已有自动更新）

### A. 手动检查与可选提醒
设置与维护页显示：当前版本号、安装版/Portable 渠道、最新已验证发布版本、版本说明和更新大小（数据可核实时）。提供“检查更新”，可选择启用定期**检查并提醒**。新用户默认不自动下载/安装程序更新；检查网络应透明告知。无网络时显示上次成功检查时间和“无法检查”，不可杜撰“已是最新版”。

### B. 安全安装流程
发现可用的同渠道版本 → 阅读变更和兼容性 → 获取官方可信发行包/校验元数据 → 用户确认下载/安装 → 校验发行身份与完整性（哈希不代表签名，应记录签名/信任级别及验证策略） → 检查活动任务与配置备份 → 提示关闭受影响服务 → 外部更新器进行替换或安装 → 重新启动 → 检查启动/模型/历史 → 失败提供恢复路径。下载成功 ≠ 验证成功 ≠ 安装成功。

- V1 不支持在原进程仍持有程序文件时危险地自我覆盖；禁止更新程序修改模型权重或删除用户私人数据。
- 更新渠道不可混用（安装器、Portable、源码）。旧 Portable 用户可走“下载新版/保留原数据”的安全指导，不强制后台自动替换整个目录。
- 遇到无法验证签名、清单、许可证或发行包身份：显示原因并阻止自动安装，不能用“下载完成”替代安全验证。
- 发布审批、真正签名、签名证书与更新源可用性均为后续工程核验项目，不能在交付前编造。
- 应用更新与 ASR 模型更新两套任务分别显示：后者遵守模型中心的独立下载队列与用户确认切换。

### C. 更新失败
断网/磁盘不足/权限失败/安装被取消/原目录占用/启动失败：不得误删老版本、旧配置、模型、历史；新版本不可用时提供旧版恢复、重新安装或保留数据引导。更新日志要记录结果但脱敏路径与凭据。版本迁移必须在安全验证后变更配置版本标记。

## 七、卸载与重装体验（V1 安装版目标）

1. Windows 正常卸载入口可触发标准卸载器，显示即将移除程序文件/快捷方式；**默认保留用户个人数据、已下载模型、热词、历史、角色和 API 私密配置**，以支持日后重装恢复。
2. 卸载前显示数据预计所在目录、占用空间与“保留数据（推荐）/删除应用管理数据”的明确选择；删除自定义数据涉及隐私和不可恢复风险，须用户主动选择并二次确认。不要只靠默认勾选“一键清空”。
3. 已在使用的听写、文件转写及下载任务在卸载前得到安全终止/暂停处理；不可对不属于本应用的服务或用户自定义目录实施递归删除。
4. Portable 不注册卸载程序时，以“便携版移除说明”引导如何保留/清理数据，不假称具备系统标准卸载入口。
5. 重装同版本或升级时应识别旧数据与配置，先预览迁移/保留、校验复制和来源，禁止先删旧目录再迁移。
6. “卸载应用”“删除模型”“清空历史”“清理日志”“删除私人数据”是不同的动作和权限边界。

## 八、诊断资料和敏感信息保护

- 最近错误应显示**当前会话相关**的事件；历史日志按时间可查，不能冒充现时故障。
- 诊断包有“选择内容→脱敏预览→保存到用户指定本机位置”流程。默认不含 API Key、完整提示词/角色私有内容、原始语音、转写全文、完整聊天/历史记录或敏感绝对路径。
- 仅由用户明确请求分享或上传，且能够预览脱敏结果后才能进行外传；不能在后台悄悄上传。
- PID 查找、端口占用和停止程序必须核实进程归属，避免 6016/6017 被无关程序占用时停止错误目标；Windows 管理员权限不是默认要求。
- 清理日志时先检测当前是否被写入，精确列出待删除文件，不能在重启/更新/故障诊断时自动清掉关键证据。

## 九、与其余 V1 模块的接口

- 首次向导/模型中心：无模型、模型下载、校验、Worker 就绪与更新切换。
- 听写/浮层：录音中重启、窗口焦点与确认浮层内容保护、热键状态异常。
- 文件转写：活动任务是否允许重启/更新；完成、失败、中断清单恢复。
- 本地数据与配置备份：升级前备份和版本迁移、诊断脱敏、卸载保留数据。
- 官网/发布：唯一正式下载渠道、版本签名/哈希、发行说明与回滚指南，待下一份安装/官网文档统一设计。

## 十、验收矩阵（供一次性交接包引用）

- 空模型打开 GUI；模型成功/加载中/失败/崩溃，顶栏、模型中心、托盘、诊断状态一致。
- 6016/6017 被其他程序占用，拒绝误识别与误终止；旧 PID/重启快照不显示已就绪。
- 重启客户端不必杀 ASR；模型切换失败能回到旧可用模型；正在录音、转写、下载时有任务保护。
- 关闭 GUI/托盘关闭/完全退出/程序异常退出的语义、下载可恢复、任务记录保留。
- Windows 安装版升级与卸载：重装前后配置/热词/私有数据哈希一致，默认不删除用户数据；卸载选择清理时仅限已核实应用管理目录。
- 更新网络失败、发行包损坏、版本渠道不一致、无签名/校验、权限/磁盘不足、安装取消、旧版回滚。
- 日志和诊断导出不含 API Key、语音内容与未同意的敏感资料。
- 现有快捷键、实时听写、文件转写、热词、LLM 角色、输入历史、Portable 模式与托盘全部回归。
- 标注「代码实现」「自动测试」「真实 Windows 设备」「用户验收」四层独立证据；未经真实测试不能声明已通过。

## 十一、待全局设计冻结前统一确定的点

1. 页面保持「服务与诊断」原名称与左侧导航；在页面底部增加「软件维护」卡，不另建主导航。
2. 关闭窗口默认保留托盘后台；完全退出要安全暂停下载、处理未完成的转写任务。
3. V1 优先做到**检查版本并提醒 + 明确下载/更新流程**；是否支持真正的自动安装，需要确定安装渠道、可信发行身份、可恢复性和技术验收后再冻结，不能因为 UI 画出按钮就当功能已实现。
4. 卸载默认保留模型与个人数据；破坏性清理需要专门的二次确认，Portable 走独立说明。
5. 实际编码先核对本地 M1-A/W01 与原工作区修改，不重写已有服务管理和托盘功能。
