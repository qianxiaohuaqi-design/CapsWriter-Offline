# W01｜本地工作区文件与 GitHub 上传候选盘点

- **状态**：已发布、等候本地只读检查
- **性质**：只读，不上传、不改动、不提交、不推送
- **基线**：先读取真实本地状态；网页端读取远端 master 于 2026-10-27 为 `d122f845`，不能作为本地最新状态的假设
- **目标**：帮助用户识别哪些已有本地成果值得纳入仓库，以便网页端/本地 Codex 共享，尤其是未跟踪的 build.spec、开发指南和测试文件。

## 先决阅读

1. 根 `AGENTS.md`；
2. `docs/项目管理/README.md` 与 `docs/项目管理/当前交接.md`；
3. `docs/CHANGELOG.md` 历史交接、当前本地差异；
4. 可用时阅读本地共享 AgentSpec Skill。

## 工作事项

1. 只读执行 `git status --short`、当前 HEAD/分支、tracked/untracked/ignored 分类；对原有 11 项作数量、状态、路径和原快照 SHA-256 对比，不修改任何文件。
2. 检查候选：`build.spec`、`docs/开发指南.md`、`tests/e2e/test_runner.py`、四个 `test_tier*.py`、原有 `.gitignore`/`readme.md` 差异；核对两个已有删除脚本究竟属于废弃还是待恢复，**不得擅自恢复/删除**。
3. 找出其他应该分享的**代码、可复现构建脚本、测试用例、技术文档、空目录占位、依赖版本说明**；列出路径、大小、用途、是否可重现与必要性，不要为了“整洁”上传大文件。
4. 检查可能包含密钥、令牌、个人绝对路径、输入文本、姓名、私人 API 配置、机器标识的文件；**只报告风险与文件路径，不输出或复制秘密值**。模型权重、私有数据、日志、音视频、转写输出、备份、下载缓存、DLL/FFmpeg/未知二进制默认不上传。
5. 对每个候选给出 **建议上传 / 需脱敏或修改后可上传 / 保留本地 / 不确定需用户审批** 四类，并说明是否会与远端文件冲突。
6. 检查 `.gitignore` 是否足以防止误上传，但不要修改；说明长期隐私文件是否需要本地 `.git/info/exclude`。
7. 归纳最终推荐的最小一组上传文件、实施前验收和回滚方法。**不得执行 `git add`、`git commit`、`git push`、`git clean`、`reset`、`checkout`、拉取后自动合并、部署或启动业务服务。**

## 交付与验收

- **仅返回只读报告**，可以引用本地代码具体行号，但不要上传任何日志、快照或用户数据。
- 报告应写本地分支/HEAD/工作区、11 项保护是否通过、候选矩阵、隐私风险、与 GitHub 差异、推荐顺序、未检查范围。
- 可将准备好的回执草稿保留在本地独立草稿位置，但**本任务禁止自动写入或推送仓库**。
- 用户及网页端审核后，另行下达独立的 W02 上传授权任务，才可以选择安全文件入库。
